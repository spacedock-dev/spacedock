## Problem

The boot-resident core, the dispatch core, the gate flow, and the merge flow each interleave three layers of concern in one prose run: the L3 *intention* (what outcome the step reaches), the L2 *mechanics* (the exact git dance, the set→invoke→clear sequence, the dispatch-build invocation), and — where a verb has shipped — the L1 *automation* the FO calls. A capable model reads through all three and reconstructs the intention; a weak (Haiku) FO re-derives the mechanics inline every session and breaks them (the `w4` spike: `«state.commit»`'s `git -C` form paraphrased to `cd && git add` 2/3, `«dispatch»` dropped `subagent_type` from the emitted envelope 3/3). The sprint's binary-verb members (`next-action`, `state-verbs`, `merge-finalize`, `gate-extract`) push those mechanics into the binary, but there is no SUBSTRATE in the contract that lets a shipped verb *replace* its hand-followed recipe without a contract rewrite. Today every verb member would have to find-and-rewrite its own region of prose; nothing makes "this op is now a binary call" a one-line flip.

The prototype (`docs/dev/_proposals/state-repo-pointer-prototype.md`) names the cure: declare each op the flow invokes as a prose-function `«fn»(arg)` whose BODY either carries the hand-followed recipe (guillemets = L2, not yet code) or names the shipped verb it calls (backticks = L1, a binary). The flow reads as L3 intention; the L2/L1 mechanics live in the bodies; migrating a step is literally `«state.commit»(slug)` → `` `spacedock state commit <slug>` `` — the invocation never moves, only the body flips notation. This task is that substrate: re-express the five named cores (`«state.boot»`, `«dispatch.next-action»`, `«gate.assemble-verdict»`, `«merge.guard»`, `«feedback.route»`) as prose-function invocations so every sibling verb member's "the verb shipped" is a body guillemet→backtick flip, not a re-authoring.

Two facts from the live tree shape the scope:

- **Zero guillemets exist in the shipped contract today** (`grep -rc '«' skills/**/references/*.md` = 0 across all 11 files). The notation is entirely prototype/proposal; this task is the FIRST landing of it into shipped scaffolding. There is no existing guillemet convention to preserve or migrate — only the prototype's grammar to adopt.
- **2y (`shared-merge-dispatch-contract`) is MERGED** (`_archive/`, PR #385/#391). It produced exactly the host-neutral cores this task restructures: `fo-dispatch-core.md` (`## Dispatch` / `## Reuse and Fresh Dispatch` / `## Dispatch Adapter` / `## Event Loop`) and `fo-merge-core.md` (`## Merge and Cleanup` / `### Ship-Local Ceremony` / `## Mod-Block Enforcement`). The dependency is satisfied; the restructure works against merged `main`, not a branch.

The deeper problem the ideation gate must settle is PROOF. This workflow's proof policy bans prose-grep over instruction files: "A string, substring, or regex match over an instruction file the model reads … never proves a behavioral claim. The matched text was written by the same implementer the check polices." A restructure whose only deliverable is contract prose is the textbook trap — "the contract now uses guillemets" is exactly the tautology the policy forbids. The completion checklist already pre-empts this: the proof must be a live FO drive or a verb-body flip, NEVER a prose-grep. The approach below is built around a check whose expected value comes from OUTSIDE the contract (the binary's command tree) plus the live drive, so the AC cannot pass by spelling.

## Proposed approach

Re-express the five cores as prose-function invocations using the prototype's grammar verbatim: `«fn»(arg)` in the flow, a `## «fn»(arg): one-line intention` declaration block with `effect` / `done-when` / `block` bullets and a `→ shipped`/`→ prose, becomes \`verb\`` migration-target line. Notation IS the migration status — guillemets = hand-followed L2; backticks = a shipped L1 verb. The flow that invokes a function never changes when its body flips.

**The five cores and their landing notation this sprint:**

| Core invocation | Region restructured | Notation NOW | Migration target |
| --- | --- | --- | --- |
| `«state.boot»()` | shared-core `## Startup` | **backtick** (already shipped) | `` `spacedock status --boot --json` `` |
| `«dispatch.next-action»()` | dispatch-core `## Event Loop` | **guillemet** (not yet shipped) | `` `spacedock dispatch next-action` `` (sibling `next-action-driver`) |
| `«gate.assemble-verdict»(slug, stage)` | shared-core `## Completion and Gates` + `present-gate` | **guillemet** (verdict stays judgment) | extract-feeds-L3; see the binarization-timing decision below |
| `«merge.guard»(slug)` | merge-core `## Mod-Block Enforcement` / `## Merge and Cleanup` | **guillemet** (not yet shipped) | `` `spacedock merge guard <slug>` `` (sibling `merge-finalize`) |
| `«feedback.route»(slug, stage)` | shared-core gated-stage block + `feedback-rejection-flow` | **guillemet** (routing is judgment-adjacent) | stays prose; the skill is the body |

`«state.boot»` lands as a backtick because `spacedock status --boot --json` already ships (verified: `spacedock --help` lists `status`; the boot roll-up is the current Startup step 5). The other four land as guillemets with their named targets, since the verbs they become are this sprint's other members (not yet merged) or are irreducibly judgment.

**The migration property is the whole point.** When `merge-finalize` ships `spacedock merge guard <slug>`, that member's deliverable includes flipping `«merge.guard»`'s body from the hand-followed set→invoke→clear recipe to "call the verb" and the notation from guillemets to backticks. The invocation `«merge.guard»(slug)` in the flow does not move. Same for `«dispatch.next-action»` when `next-action-driver` ships. The restructure is the substrate that makes each of those a one-body-flip, not a prose hunt.

**Scope discipline — re-EXPRESS, do not REWRITE.** The restructure preserves every behavioral rule the current cores carry (the rebase-conflict halt, the mod-block guard's mechanism-level enforcement, the reuse conditions, the AC cross-check). It relocates mechanics from the inline flow into function bodies and adds the invocation layer; it does not change what any rule DOES. This is the guard against the staff review's stated risk ("the safety property being silently dropped in the re-expression"): the structural check below pins behavioral anchors, and the live drive observes the behavior unchanged.

### The non-grep proof mechanism (resolves checklist item 1)

The behavioral AC binds the contract's notation to an INDEPENDENT oracle that can diverge from it — the binary's actual command tree — plus a live drive. Two halves:

1. **Verb-notation ↔ shipped-command binding (a contractlint structural check, NOT a prose-grep).** A new check in `internal/contractlint` walks the restructured cores, extracts every backtick `` `spacedock …` `` verb token AND every `«fn»` guillemet declaration's `→` migration-target, and binds each against the cobra command tree the binary actually ships. The oracle is enumerated from `newRootCommand(...).Commands()` (recursively — `dispatch` yields `build`/`show-stage-def`/`trunk`/`reconcile`; `state` yields `init`), NOT from `--help` text. The invariant: **a backtick verb MUST resolve to a shipped command; a guillemet's named target MUST NOT yet be shipped (else it should have flipped).** The expected value comes from the compiled binary's registry — an independent source the contract prose cannot author — so a contract that backticks `spacedock merge guard` before the verb ships FAILS the check, and a guillemet whose target verb has shipped FAILS as "should have flipped to backtick." This is the same shape as the existing `boot_resident_closure_test.go` (filesystem `os.Stat` oracle, with a RED control), extended to the command-registry oracle. It is explicitly NOT the banned heading-present/absent grep — it binds two independently-authored values (contract token, binary command set) that diverge under exactly the migration mistake we want to catch.

2. **The verb-body flip is a real, observable migration event.** The sprint's `state-verbs` / `merge-finalize` / `next-action-driver` members each ship a verb. When one ships, this restructure's corresponding body flips guillemet→backtick, and the check from (1) re-binds against the now-shipped command. The flip — not its prose — is the gradable event: before the flip the check requires the target ABSENT; after, PRESENT. This is the "verb-body flip" proof the completion checklist names.

3. **The live drive (the sprint gate, not this member's to run).** `haiku-drive-validation` (sequenced last) drives a Haiku FO through the restructured contract end-to-end. That drive — durable end-state + captured tool-call stream, never transcript prose — is where "the restructured flow is still operable" is OBSERVED. This member does not run that drive; it ships the substrate the drive exercises and is graded by the structural check (1) plus a focused single-core operability spot-check (AC-3 below), with the full operability proof riding the sprint's terminal drive.

### `«gate.assemble-verdict»` binarization-timing (resolves checklist item 2 — surfaced as a captain gate decision)

**Recommendation: keep `«gate.assemble-verdict»` a prose-function (guillemets) this sprint; do NOT ship a `spacedock gate assemble-verdict` binary.** Rationale, grounded in the sibling state and the proof policy:

- The verdict (approve/reject, is-this-AC-satisfied, is-this-chosen-direction-sound) is irreducible JUDGMENT. `6re`'s entire design rests on the verdict NOT being binarized — it ships the three extract MODES (`--checklist`, `--ac-scan`) that feed L3 structured input and explicitly route the verdict to L3 (`6re` Out-of-scope; `present-gate` rule 5; `72`'s `«gate.route-verdict»` authoring). Binarizing the verdict would contradict the sprint thesis ("Haiku adjudicates none alone") and `72`'s safety mechanism.
- The body of `«gate.assemble-verdict»` therefore decomposes into: (a) deterministic EXTRACTION → already becoming `6re`'s `status --read --checklist`/`--ac-scan` modes (backtick sub-calls once `6re` merges), and (b) the verdict DECISION → routes to L3 via `72`'s `«gate.route-verdict»` for a level-2-only FO, or the FO's own `present-gate` `Recommend` line for a capable FO. The prose-function body names both halves; neither is a NEW `assemble-verdict` binary.
- This matches the sprint index's stated default (`Out of scope`: "`spacedock gate assemble-verdict` as a shipped binary — the verdict decision tree may stay a prose-function this sprint … unless the captain pulls it in"). The recommendation is to NOT pull it in: the L3 route is the safety mechanism either way, and the extract modes already remove the deterministic variance.

**Captain decision asked:** ratify keeping `«gate.assemble-verdict»` as a prose-function with its body naming (a) the `6re` extract modes and (b) the L3/`present-gate` verdict route — OR pull a `spacedock gate assemble-verdict` binary into this sprint (which would re-open the verdict-is-judgment boundary `6re`/`72` settled). The body's guillemet notation and `→ prose` target encode the chosen answer.

### Shared-core landing-order co-design (resolves checklist item 3 — surfaced for captain-ratify)

The restructure re-touches three boot-resident regions — `## Startup`, `## Completion and Gates`, `## FO Write Scope` — that two in-flight siblings also edit. Verified live-tree state:

Its own staff-review finding #7 / #5 explicitly flags: "Co-design or sequence `72`'s shared-core edits with the post-2y `prose-function-restructure` (same three regions)."

**Recommendation: the restructure lands LAST of the three; `6re` and `72` land their raw-prose edits first, and the restructure re-expresses on top.** Rationale:

- `6re` step-4 is the lowest-risk and most-progressed (a single-step source swap, already implemented on a branch). Landing it first means the restructure's `«state.boot»`-region re-expression incorporates the `status --read` taxonomy source as settled fact, not a moving target.

**Captain decision asked:** ratify the landing order **`6re` → `72` → restructure** (restructure re-expresses the merged step-4 + step-1.5 edits into prose-function form, folding `«fo.tier»()` in as a sixth declared prose-function). The risk if mis-ordered is a rewrite collision in the three shared regions and a silent drop of `72`'s safety property; this order makes the restructure the single place the notation is authored.

## Out of scope

- **Shipping any of the binary verbs** (`spacedock dispatch next-action`, `spacedock state ready|sweep|commit`, `spacedock merge guard`, `spacedock gate …`). Those are the sibling members (`next-action-driver`, `state-verbs`, `merge-finalize`, `gate-extract`). This member ships only the SUBSTRATE — the prose-function invocations and bodies — so that each verb's landing is a one-body flip. The bodies of not-yet-shipped verbs stay guillemets with named targets.
- **Binarizing the verdict** (`spacedock gate assemble-verdict`). Recommended kept prose this sprint (see the binarization-timing decision); the verdict is judgment and routes to L3.
- **Changing any behavioral rule.** The restructure re-expresses; it does not alter the rebase-conflict halt, the mod-block enforcement, the reuse conditions, or the AC cross-check. A behavior change is a different task.
- **Codex / Pi adapter restructure.** The host-neutral cores (`fo-dispatch-core`, `fo-merge-core`) and the shared core are restructured; the per-host runtime adapters keep their current prose unless a core invocation forces an adapter-side rename. Codex/Pi layered-FO operability is a 0205 follow-up.
- **The `haiku-drive-validation` live drive itself.** That is the sprint's terminal member; this task ships the contract it drives and is graded by the structural check + a focused spot-check, with the full operability proof riding the terminal drive.
- **Authoring the five sibling verbs' first tests.** Each verb member owns its own TDD; this member's flip-point only requires that the structural check re-binds when a verb ships.

## Acceptance criteria

Each AC names a property of the finished restructured contract and how it is verified by an EXTERNAL oracle (the binary's command tree, the filesystem, a live drive) — never a string/substring/regex match over the contract prose the implementer wrote.

**AC-1 — A contractlint structural check binds every backtick verb to a shipped command and every guillemet's migration-target to an un-shipped one, and goes RED when the binding is violated.**
The restructured cores carry `«fn»` invocations whose bodies are backticks (shipped verbs) or guillemets (named-target prose-functions). A new `internal/contractlint` check extracts each backtick `` `spacedock …` `` token and each guillemet's `→` target, and binds them against the cobra command tree enumerated from `newRootCommand(...).Commands()` (recursive). A backtick verb absent from the command tree, or a guillemet target PRESENT in it (should-have-flipped), fails the check.
Verified by: a Go test in `internal/contractlint` asserting (a) every backtick verb in the restructured cores resolves to a shipped cobra command (the command tree is the oracle — adding a phantom backtick verb to a test fixture fails the bind), and (b) a RED control (mirroring `boot_resident_closure_test.go`'s `…GuardFailsOnDanglingTarget`) that plants a backtick verb the binary does not ship and proves the check goes red, plus a guillemet whose target IS shipped and proves the should-have-flipped failure. The cobra registry — not the contract text — is the expected value; a valid paraphrase of the prose does not pass, an un-shipped backtick does not pass.

**AC-2 — The restructure preserves every behavioral anchor the current cores carry; the existing boot-resident closure and host-neutral-core ceremony checks stay green.**
After the restructure, `internal/contractlint`'s `TestBootResidentDeferredLoadPointsResolve` and `TestHostNeutralCoresResolveAndCarryCeremony` pass — every deferred load-point still resolves on disk and each host-neutral core still carries its four ceremony anchors (`## Merge and Cleanup`, `### Ship-Local Ceremony`, `### Worktree removal safety`, `## Mod-Block Enforcement`; `## Dispatch`, `## Reuse and Fresh Dispatch`, `## Dispatch Adapter`, `## Event Loop`). The restructure relocates mechanics into function bodies without dropping a load-point or a ceremony region.
Verified by: the existing `internal/contractlint` suite (and `internal/dispatch`, `internal/ensigncycle`) passing green against the restructured contract — these are the structural checks 2y's extraction is already held by; their continued green proves the re-expression did not drop an anchor. The ceremony-anchor set is the independent oracle (a dropped `## Mod-Block Enforcement` fails `TestHostNeutralCoresResolveAndCarryCeremony`).

**AC-3 — One representative core's prose-function form is operable: a focused live exercise drives the restructured region and reaches its on-disk outcome.**
For one already-shipped-verb core — `«state.boot»()` (backtick, `spacedock status --boot --json`) — a focused exercise confirms the restructured flow's invocation resolves to the real shipped behavior: invoking the named verb against the real `docs/dev` workflow returns the boot roll-up the restructured `## Startup` flow consumes. This proves the prose-function form points at real behavior for the one core that can be exercised today, ahead of the sprint's terminal full-loop drive.
Verified by: a behavioral exercise that runs `spacedock status --boot --json` against the real workflow and confirms it returns the boot sections the restructured `«state.boot»()` invocation names (the same exercise the current step 5 is proven by) — the binary's output is the oracle, not the contract prose. The full multi-core operability proof (every restructured core driven by a Haiku FO) is `haiku-drive-validation`'s, explicitly deferred to it.

**AC-4 — Each not-yet-shipped core's body names its migration-target verb so a sibling member's verb-landing is a one-body flip.**
Every guillemet core (`«dispatch.next-action»`, `«merge.guard»`, and `«gate.assemble-verdict»`/`«feedback.route»` per the decisions above) carries a `→` line naming the binary verb it becomes (or `→ prose` for the verdict/route that stays judgment). When a sibling member ships its verb, flipping that one body's notation guillemet→backtick is the only contract change needed, and AC-1's check re-binds against the now-shipped command.
Verified by: AC-1's check is the enforcement — it requires every guillemet to carry a resolvable `→` target and every backtick to be shipped, so the migration-target presence is structurally checked, not prose-asserted. A flip exercised at implementation (flip one already-shippable body, re-run AC-1's check, observe it re-binds green; flip it back) demonstrates the one-body-flip property against the real check, not against prose.
