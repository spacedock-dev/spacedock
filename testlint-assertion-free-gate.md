New internal/testlint package: a hard-fail structural check (mirroring internal/contractlint's architecture) that fails a test/subtest reaching no failure-triggering assertion, directly or through a same-package helper -- riding the existing go test ./... sweep, no new CI tooling. Must merge after the sibling tautological-test-fixes entity, not before.

## Problem

A test whose body reaches no failure-triggering call on its `testing.T`/`testing.TB` handle passes no matter how the behavior under test breaks — it is coverage theatre. docs/dev's Proof policy catches this only reactively, at high-stakes-surface merge time, via human judgment. There is no standing, automatic check. The audit that seeded the sibling `tautological-test-fixes` entity confirmed at least one such live defect by mutation: `internal/ensigncycle/pty_session_test.go:379` `TestFOSessionPinning/activeSessionFile_would_flip_to_teammate`, whose only failure-path call is `t.Logf` (`:384`) — it passes for any return value of `activeSessionFile`.

The `assertion-free` shape (a test/subtest that never reaches a failure sink) is machine-detectable structurally, unlike the `mirror-assertion` shape (which needs value-provenance reasoning and is deliberately routed to a reactive audit trigger by the sibling `anti-tautology-enforcement-and-template-gap` entity, NOT to an AST gate). This entity ships the standing structural gate for the assertion-free shape only.

## Approach

New sibling package `internal/testlint`, architecturally mirroring `internal/contractlint` (a `doc_test.go` charter stating the package policy + `go/ast`-based structural-check `_test.go` files). It rides the existing unconditional `go test ./...` CI sweep with zero new tooling or pipeline: the check IS a Go test, so it runs wherever `go test ./...` already runs.

ONE hard-fail check, `TestNoAssertionFreeTests`, walks the repo tree (repoRoot derived from the package source dir, `../..`, exactly as contractlint's `repoRoot` does; `.git`/`.worktrees`/`.claude`/`vendor`/`testdata` pruned) and fails any top-level `TestXxx(t *testing.T)` or `t.Run` closure that reaches no `t.Error*`/`Errorf`/`Fatal*`/`Fail*` call on its testing handle, directly or via a same-package helper resolved by a **fixed-point closure over FuncDecls** (seed the `asserts` set with functions that call a sink directly, then iterate adding callers-of-callers until the set stops growing). `t.Skip`/`SkipNow`/`Skipf` are treated as exempting calls — a skipped test is intentionally assertion-free. A top-level test that only dispatches subtests (`t.Run` on its own testing param) is not itself scanned; its subtests are judged individually. An unresolvable case needs a `// testlint:allow-empty <reason>` comment, reviewed like any suppression.

Three spike-to-production corrections (fable's independent review, all three confirmed against the live repo this ideation — see Spike determination):

1. **`t`-as-argument sink rule.** Extend the sink test: any call passing the testing param `t` AS AN ARGUMENT (not only methods called ON `t`) counts as a potential sink. This clears the one genuine false positive — `internal/dispatch/build_advance_contract_parity_test.go:192`, whose subtest asserts through a func-typed struct field `row.check(t, out.Prompt, body, fixture)` in a table-driven pattern that name-based FuncDecl closure structurally cannot see — while still flagging the pty subtest (`t.Logf` is a method ON `t`; that subtest never passes `t` as an argument anywhere). This is a deliberate soundness-over-completeness tradeoff: passing `t` to a non-asserting helper would under-flag, the safe direction for a hard-fail gate.
2. **Subtest FuncLit real parameter name.** Read the `t.Run` closure's actual first-parameter name instead of hardcoding `"t"` (subtests routinely rebind, e.g. `func(subT *testing.T)`); an unnamed `_` param cannot host a sink, so it is treated as no-sink.
3. **`hasRunCall` restricted to the testing param.** Only `Run` called ON the testing param exempts a top-level test from scanning. The spike's naive version treated ANY `.Run(` call — including `exec.Cmd.Run()` — as an exemption, wrongly skipping real tests.

Corrected accounting (the design's first draft and its own verify pass both mis-stated this; fable's independent second pass caught it, and this ideation reproduced it a third time): the naive zero-direct-sink version flags 34/383 subtests (too noisy to ship); the fixed-point extension resolves to 0 top-level + exactly 2/381 subtests; the `t`-as-argument fix drops that to exactly **1/381 subtest**. That one residual flag is the **confirmed real bug** this checker exists to catch (the pty subtest, sibling `tautological-test-fixes`, already ideation-approved) — NOT a false positive. Zero genuine false positives remain.

**Sequencing dependency (both review passes flagged this independently, and it is self-enforcing).** This checker must not merge before the sibling `tautological-test-fixes` fix for `pty_session_test.go` lands. On a tree where that fix is absent, `TestNoAssertionFreeTests` is RED (it flags the still-assertion-free pty subtest) — so merging this gate first either breaks CI on an unrelated PR, or pressures someone to reach for `// testlint:allow-empty` to silence the exact bug the gate exists to catch. The gate must go GREEN at merge by the sibling fix landing first, NOT by suppressing the pty subtest.

## Acceptance criteria

- **AC-1 (value — classifier ground truth on a fixture corpus, against a baseline that moves the wrong way).** The finished classifier, run over `internal/testlint/testdata/` fixtures with hand-declared ground truth, produces EXACTLY the expected flag set: it FLAGS the assertion-free shapes (a subtest whose only failure-path call is `t.Logf`, reproducing the pty bug shape; a top-level test that reaches no sink) and does NOT flag the asserting shapes — a subtest calling a func-typed struct field with `t` passed as an argument (`row.check(t, …)`, reproducing `build_advance_contract_parity_test.go`), a test asserting only through a same-package transitive helper (callers-of-callers), a `t.Skip(reason)`-only test, a subtest that rebinds its param (`func(subT *testing.T){ subT.Errorf(…) }`), and an assertion-free test carrying `// testlint:allow-empty`. Independent baseline that moves the wrong way: with the `t`-as-argument sink rule removed, the classifier flags the func-typed-field fixture (a false positive) and the ground-truth comparison goes RED. Tested by: a table-driven `go test ./internal/testlint` fixture test asserting the classifier verdict per fixture equals its declared ground truth; the func-typed-field fixture is unflagged only with the `t`-as-argument rule present.
- **AC-2 (value — zero false positives across the whole live corpus, against a measured baseline).** At merge HEAD, `go test ./internal/testlint` is GREEN: the gate flags 0 of the ~886 top-level tests and 0 of the ~381 subtests across the real repo — including the `row.check` func-typed-field pattern and every transitive-helper pattern. Independent baseline that moves the wrong way: the naive zero-direct-sink classifier flags 34 subtests and the fixed-point-without-`t`-as-argument classifier flags 2 (1 of them the `row.check` false positive) on the same tree; the finished gate flags 0 once the sibling fix has landed. Tested by: `go test ./internal/testlint -run TestNoAssertionFreeTests -count=1` GREEN at HEAD, plus a recorded count from running the classifier without the `t`-as-argument rule showing ≥1 flag (the `row.check` false positive) on the identical tree.
- **AC-3 (sequencing is self-enforcing).** On a tree WITHOUT the sibling `tautological-test-fixes` fix, `TestNoAssertionFreeTests` is RED and names exactly the `activeSessionFile_would_flip_to_teammate` subtest (and does NOT name `row.check`); the entity reaches GREEN only after that sibling fix lands, and does so WITHOUT any `// testlint:allow-empty` on `pty_session_test.go`. Tested by: run the gate against pre-sibling-fix `pty_session_test.go` (or the captured pre-fix subtest as a testdata fixture) → RED flagging exactly that subtest; and `git grep -n 'testlint:allow-empty' internal/ensigncycle/pty_session_test.go` returns nothing while the gate is GREEN at merge.
- **AC-4 (escape hatch works and is scoped).** An assertion-free test carrying `// testlint:allow-empty <reason>` is NOT flagged; the identical test with the comment removed IS flagged; and the comment suppresses only the case it annotates, not sibling tests in the same file. Tested by: paired testdata fixtures (with/without the comment) in the AC-1 corpus asserting flagged/unflagged, plus a fixture with one suppressed and one live assertion-free test in the same file asserting only the un-annotated one is flagged.
- **AC-5 (architecture mirror + zero new CI surface).** The package ships a `doc_test.go` charter stating its policy (mirroring `internal/contractlint/doc_test.go`), the check runs purely as a Go test under the existing `go test ./...` sweep, and no CI config, Makefile target, workflow YAML, or new binary/tool is added. Tested by: `go test ./internal/testlint` runs the gate with no arguments and no external tooling; a diff review confirms only files under `internal/testlint/` are added and no `.github/`, `Makefile`, or build-config file changes. (This AC asserts the mechanism shipped; it counts only paired with the value ACs AC-1/AC-2 it serves.)

## Notes

- The `t`-as-argument rule is intentionally conservative: a test passing `t` to a helper that never asserts would be under-flagged (a false negative). This is the safe direction for a hard-fail gate and matches fable's settled recommendation; tightening it would require type resolution (go/types), which the design deliberately avoids to stay a zero-dependency AST check.
- Nested subtests (a `t.Run` closure containing only further `t.Run` calls and no direct sink) are judged by the same rule as any subtest; the settled design does not add a subtest-level `hasRunCall` exemption. If a future real case surfaces one, it is a follow-up, not in scope here.
- The ~886/~381 live counts will drift as the repo grows; the ACs pin the classifier's BEHAVIOR (ground-truth verdicts on fixtures, zero false positives on whatever the live corpus is at merge), not the absolute counts.
