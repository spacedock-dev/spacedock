The live-e2e "flake" is root-caused from captured evidence (CI run 26839572693, both legs): the CI live-e2e environment does NOT put the built `spacedock` binary on the FO subprocess's PATH, so the FO's first contract step — `spacedock --version` — fails with `command not found` and the FO correctly ABORTS via the #262 binary-absent gate. This is a 4th cause, distinct from the original H1/H2/H3 framing. It is NOT the teams-vs-`-p` precedence (old H1), NOT contract-load model nondeterminism (old H2), NOT the `-p` await semantics (old H3), and NOT an 02-branch (retire-python-oracle) regression. The fix is TEST-INFRA: put the built binary on the FO subprocess's PATH. Once that lands, the FO drives past the binary gate and the cycle can proceed.

## Root cause (code-grounded)

The chain, confirmed against the code and the captured transcripts:

1. `.github/workflows/runtime-live-e2e.yml` builds the binary with `go build -o ./spacedock ./cmd/spacedock` and records ONLY `SPACEDOCK_BIN=$(pwd)/spacedock` in `$GITHUB_ENV` (line 125-126). It does NOT add `$(pwd)` (the built-binary's directory) to `$GITHUB_PATH`. By contrast the Claude Code install step DOES add its dir: `echo "$HOME/.local/bin" >> "$GITHUB_PATH"` (line 121). So the runner's PATH gets the `claude` dir but never the `spacedock` dir.
2. `internal/ensigncycle/live_test.go` shells the FO via `cmd := exec.Command(binary, "claude", …)` where `binary` resolves from `SPACEDOCK_BIN` (the absolute path) — so the FO BINARY itself launches fine. But the child environment is `cmd.Env = childEnv`, and `childEnv` comes from `isolatedClaudeEnv` (`liveenv_test.go`), which is `os.Environ()` (via `cleanEnviron`) with only `CLAUDECODE`/`HOME`/credential keys dropped/overridden. PATH is inherited verbatim — and since `$(pwd)` was never added to the runner PATH, the FO subprocess's PATH has no `spacedock`.
3. The FO contract's FIRST startup step (`skills/first-officer/references/first-officer-shared-core.md:7`, the #262 gate) is: run `spacedock --version`; if it is not found, ABORT with the install hint and do NOT proceed to discovery. `SPACEDOCK_BIN` is an env var the test sets for ITS OWN binary resolution — the FO contract does not read it; the FO only knows `spacedock` by PATH name.
4. So `spacedock --version` → `command not found` → the FO aborts (sonnet) or improvises a symlink and then discovers the wrong root (opus). Either way: no TeamCreate, watcher trips, live-e2e RED.

The defect is squarely in the test harness (the workflow's PATH wiring + the test's child env), exactly as the captain scoped it — NOT in the FO runtime/contract (which is behaving correctly) and NOT in the status lane.

## The fix (TEST-INFRA)

Put the built `spacedock` on the FO subprocess's PATH. The test already KNOWS the binary path (`spacedockBinary(t)` returns the absolute path resolved from `SPACEDOCK_BIN` or a PATH lookup), so the minimal, machine-independent fix is at the test's child-env seam:

- **Primary fix (offline-unit-testable): prepend the binary's directory to the child env's PATH.** Add a pure helper alongside `isolatedClaudeEnv` (in `liveenv_test.go`) that takes the resolved binary path and the child env, prepends `filepath.Dir(binary)` to the `PATH=` entry (preserving the rest), and returns the augmented env. `live_test.go` calls it after `isolatedClaudeEnv` so the FO subprocess resolves `spacedock` by name. This fixes BOTH CI and local runs (local: a stale `spacedock` on PATH no longer shadows the just-built `SPACEDOCK_BIN`) and is the seam an offline unit test asserts.
- **Belt-and-braces (CI yaml): add the build dir to `$GITHUB_PATH`.** In the build step, after `go build -o ./spacedock`, also `echo "$(pwd)" >> "$GITHUB_PATH"` (mirroring the claude-install step's line 121). This makes the runner PATH correct independent of the test, so any other CI step that shells `spacedock` also works. The test-level fix is authoritative; this is the broader-correctness companion the captain named ("maybe the workflow yaml").

The test-level fix is preferred as the PRIMARY because (a) it is offline-unit-testable (AC-2's fix path wants a red-without/green-with unit test with no model spend), and (b) it removes the silent-shadowing footgun locally. The yaml change alone would fix CI but leaves the local seam relying on whatever `spacedock` happens to be on PATH.
