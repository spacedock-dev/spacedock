The three shipped commission templates restate universal rules that already live in the FO/ensign operating contract. Restructure them the way the dev README was just slimmed (commit `48edae4c`): lead with the workflow's outcome, defer universal rules to the contract, and keep only each shape's workflow-specific rules in a dedicated slot. Every commission session then reads leaner, non-stale scaffolding, and the template's rule prose can no longer drift from the contract it paraphrases.

## Problem

`skills/commission/references/templates/development.md`, `experiment.md`, and `refinement.md` each restate rules the FO/ensign contract already owns:
- proof discipline (development.md's "Recommended practices" ~L111-137: external-proof ACs, live-scenario, detached audit) restates the contract's "prefer a code gate over a prose-only rule" and the ensign's "prove by exercising, not re-reading";
- generic stage semantics (the Inputs / Outputs / Good / Bad bullets) restate the universal stage shape per stage across all three;
- AC-must-be-testable and lead-with-the-end, both already universal.

**Where the read cost actually lands.** Commission consumes a template in two distinct steps (verified against `skills/commission/SKILL.md`):
- **Phase 1 / Trait Detection** (`SKILL.md` L116) `Read`s the *whole* selected template file into the commission session's context, then follows its `## Adoption` section. This is where the bloat is paid — every commission of that shape reads the restated doctrine, whether or not it ever uses it.
- **Phase 2 / Generate** (`SKILL.md` L256, L316-430) writes the commissioned README from the **inline** structure in SKILL.md, auto-generating per-stage `Inputs/Outputs/Good/Bad` *specific to the mission* — it does NOT copy the template file's per-stage prose. The refinement template states this explicitly (L210: per-stage bullets "are auto-generated by commission Phase 2b … not pre-baked here").

So the template's per-stage prose is pure **reference/illustration** read at Phase 1, never copied forward; slimming it cuts commission-session read cost without changing what the commissioned workflow looks like. The one load-bearing exception is development.md's "Recommended practices" block, which is an *opt-in adoption instruction* (L113: "Adopt them by copying the guidance into the `validation` stage's Outputs and Bad lists above") — its dev-shape-specific disciplines must survive the restructure, only their restated universal backbone is deferred.

The duplication also means the template copies drift independently of the contract they paraphrase: a fix to the contract's proof rule (e.g. ey's independent-source rule) does not reach a paraphrase frozen in a template.

## Proposed approach

Mirror the three dev-README slim moves (`48edae4c`) into each template, in the template's own voice. The moves:

**Move A — lead with the end.** Each template's opening paragraph states the workflow's outcome/value before its mechanics. development.md and experiment.md mostly do this already (development: "Tasks move … and land via PR review"; experiment: "Each experiment is a hypothesis tested through tiers of evidence"); refinement.md's opening leads with "Iterate on an artifact through stages of improvement" — keep the value-first lead and ensure the *first sentence* names the outcome, not "what this is."

**Move B — defer the universal rules to the contract.** Add to each template a short `## Workflow-specific rules` section whose opening sentence defers generic stage semantics and proof discipline to the FO/ensign contract (the precedent wording is the README's new Proof-policy lede: "The FO contract's Operating Principles and Working Principles already govern generic proof discipline … Tasks in this workflow inherit that. The rules below add the {shape} specifics."). Then **remove the restated universal doctrine** from the template body:
  - development.md: replace the long restated paragraphs of "Recommended practices" (L111-137) with compact dev-shape pointers (see Move C / the per-template shape below). The universal backbone — "prove by exercising not re-reading," "code gate over prose-only," AC-must-be-testable, stage semantics — is deferred, not restated.
  - experiment.md / refinement.md: they carry no separate doctrine block, so the defer is a one-line note at the head of (or replacing) their generic per-stage prose.

**Move C — compact the per-stage `Good/Bad`.** The per-stage `Inputs/Outputs/Good/Bad` bullets are reference-only (Phase 2b auto-generates the commissioned README's stage bullets; the template's are illustration). Compress each stage to a one-line shape description plus any genuinely *shape-specific* note (development's `validation` fresh-agent independence, experiment's `holdout` out-of-sample independence, refinement's `review` human-in-the-loop bar). Drop the bullets that merely restate the universal "be specific / don't hand-wave" stage shape.

**The `## Workflow-specific rules` slot — what each shape keeps (the 3-5 unique rules):**
- **development.md:** the repo-mutation worktree layer (impl + validation run in a worktree; validation is `fresh`), the pr-merge mod offer (PR state on the `pr` field, no `pr_open` stage), and the dev-shape *opt-in* proof disciplines as **pointers** — test-first authoring, external-proof ACs, detached adversarial audit, live-scenario-for-runtime-claims — each kept as a one-or-two-line opt-in note (these are dev-specific and get copied into the commissioned validation stage per L113), with their generic justification deferred to the contract.
- **experiment.md:** falsifiable-hypothesis + success-criteria-fixed-before-evidence, the smoke/run/analysis/holdout tier-gating discipline, holdout out-of-sample independence, the parked-stages layer + silence-watcher offer.
- **refinement.md:** the human-in-the-loop quality bar (review is an approval gate, polish is cosmetic-only), the variant menu (outreach / integration / content-production / prd-authoring), and the "universal base shape; no layers by default" note.

**The `## Adoption` section stays intact in all three.** It is load-bearing commission machinery (pre-fill stages, apply layers, offer mods, inject snippet, surface variants, confirmation prose) consumed at Phase 1 — the restructure does not touch it beyond the development "Recommended practices" cross-reference (L113), which is reworded to point at the new `## Workflow-specific rules` slot.

## Acceptance criteria

Each AC names a property of the finished scaffolding, not a stage action, and how it is verified — proof is behavioral or binds an independent source that can diverge, never a prose-grep over the template (a substring match over a file the model reads asserts only that we wrote what we wrote).

**AC-1 (behavioral, the load-bearing proof) — A workflow commissioned from the restructured `development.md` still governs by the universal rules even though the template no longer restates them.** The rules reach the commissioned workflow through the contract its FO loads at boot, not through restated template prose; removing the restatement does not remove the governance.
Verified by: a **live commission spike** — dispatch a real agent that runs `Skill(skill="spacedock:commission")` against the restructured `development.md` for a code-shipping mission, producing a commissioned workflow. Then **boot that commissioned workflow's first officer** and drive the universal-rule check: seed an entity whose only AC is a presence-oracle over an instruction file (a tautological proof) and confirm the FO/validator REJECTS it and demands a behavioral proof. Grade on durable end-state — the rejection / routed feedback in entity frontmatter + report — never transcript phrasing, with an offline negative that reds the grader on a wrongly-accepted end-state. Crucially, confirm the commissioned README does NOT itself restate that rejection rule (`grep` proves *absence* in the generated README — absence is a legitimate structural fact, unlike presence), so the rejection is attributable to the contract, not the template. **Dependency: this behavior presupposes the contract carries the rule** — i.e. ey has landed (or the existing contract sections already carry) the discipline the FO applies; this AC proves the *defer composes* (governance survives removal), which is this task's distinct contribution, not ey's rule-port. Development is the single live representative (captain-named primary shape); experiment/refinement are covered structurally (AC-2/AC-3) plus a no-spend commission dry-check (test plan).

**AC-2 (single-source structural invariant) — the universal-rule doctrine lives in exactly ONE place (the contract), not duplicated across the templates.** Each template carries a `## Workflow-specific rules` slot with only that shape's unique rules; the generic doctrine the templates used to restate is absent from all three template bodies.
Verified by: a contractlint-style **single-source check** modeled on `internal/contractlint` `TestStartupGateGuidanceHasSingleSource` (walks `skills/`+`agents/` markdown, asserts a set of universal-doctrine markers appears in exactly one file — the contract — and FAILS if a second copy reappears in a template). This is NOT a presence tautology: it binds two independent, divergeable things (contract content vs. template content) and reds precisely when someone re-restates the universal rule in a template (drift regression). Pair it with a `## Workflow-specific rules` heading-presence assertion per template (structural absence/presence of a section, a machine-checkable property, not a doctrine-substring match). Lives in `internal/contractlint` alongside the existing structural checks; no model spend.

**AC-3 (structural) — each template's opening section names the workflow's outcome before its stage mechanics.** Lead-with-the-end shape is structurally present.
Verified by: a structural opening-section check (the template's first prose paragraph, between the frontmatter and the first `##` heading, exists and precedes the `## File Naming` / `## Stages` mechanics) — a positional/ordering assertion over the three template files, not a value-judgement substring match. The qualitative "does the lede actually lead with value" judgement is a **gate-review item** (the FO/captain read the before/after at the ideation and validation gates), not a machine assertion, since lede quality is not mechanically decidable. Recorded honestly: AC-3's machine half proves *a lede section exists in the right position*; the *quality* half is human-gated.

**Proof-shape honesty note.** This is prose scaffolding. The only fully behavioral proof is AC-1's live commission + rejection drive (development). AC-2 and AC-3 are structural invariants that bind independent sources or assert positional/structural facts — legitimate per the proof policy because they can diverge and fail, unlike a doctrine-substring match. No AC is satisfied by grepping the template for the words it was supposed to contain.
