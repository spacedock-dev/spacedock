## Observations

### Agent reflection (requested): what would have happened without spacedock

This is the part the user asked for — an honest counterfactual about working with vs without the workflow tool, from the agent that drove it.

**1. On MECHANICAL correctness, the tool won decisively.** The first ideation design's three worst defects were all caught by the staff-review layer, not by me, not by CL: NF1 (sandbox detection reading `--version` output that *cannot exist* in the exact class where the protection is needed — every gate has it, so detection was vacuous in exactly the install-offer context), NF2 (a loop-bound "guardrail" that was prose discipline in env clothing, with no cross-tool-call durability on ANY of our runtimes), and B2 (the gate's own `SPACEDOCK_BIN` repoint colliding with the shared-core launcher invariant I'd written last week). None of these would have been caught by a solo agent reading the code. NF1 in particular is the kind of blind spot that persists because once you write "detect via `^Sandbox:` output", the reader confirms *syntax* (the parse is right) instead of *reachability* (there's no binary to produce the output). Three independent reviewers found these in three passes — each fresh context found a different class of problem than the prior. Walden iterated until the reviewer declared closed-in-substance, not until the author ran out of ideas. Left alone, my cycle-1 design would silently have satisfied none of the three ACs where they matter most — clean syntax, broken semantics.

**2. On EVIDENCE LEGIBILITY, the tool earned its keep doubly.** First, the binary-across-the-board verification trail (frontmatter digests, bound Briefings, provider packages, per-attempt resolutions) meant the captain could test-drive the candidate **as a thing with an identity** — he read the same artifact I'd signed; there was no "trust me, I checked." Second, he still held the gate because the summary blob wasn't legible: "very hard to check what evidence you have already gathered, and what requires me to test manually." That hold is the tool's win and its cost in one: the gate stopped the ceremony, but the stop revealed the presentation layer isn't doing its job for a non-author reader. The recorded-resolution system was built for audits; the *summary* is for humans, and it was the weakest part.

**3. On PROCESS DISCIPLINE, the tool kept me honest in ways I would have cut.** The version gate caught that my local binary was 0.26-built and the skills wanted 0.27 — an easy, quiet thing to skip (CL said ignore-drift; the binary note is filed). The file-verification-after-completion caught an ensign that wrote the summary to the output artifact instead of the entity — without it, the next worker would have stared at a nearly-empty file and rebuilt from scratch. The `status --next`-suppressed-backlog check forced me to acknowledge backlog is gate:blocked, and the mod-block guard blocked me from early terminalizing while the merge hook was pending. Each stop was cheap and correct. **Without it, I'd have skipped three of them.** I know this because the one the tool didn't have a guard for, I DID skip: my first gate presentation was thin (three DONE bullets, no evidence-to-test map), and it took a captain hold to make it explicit.

**4. Where the tool HURT — and it's real, not a rounding error.** The ceremony cost was very high for one task: 4 ensign redispatches (cycle 1, completion-fix, cycle 2, cycle 3, cycle 4), 3 adversarial reviewer spawns, a completion-gap respawn, plus 3 dead-provider 503s, plus the two gate-record refusals and the subspace re-presentations. Time-wise this session burned several hours of CL's and my context on ONE task, two binding annotations included. Some of that is force-multiplied value (the three reviewed catches are the product; the fix-in-place loops are the fix). Some is the tool's own cost-of-service: dispatch-stamping model overrides by hand every time because `model: opus` from the dev README is outside pi's dispatch-settable space; the HTTPS push failing every commit; the subspace presentation being hand-staged per gate. **Idle observation: the same ceremony that feels heavy on day one also surfaced a semantic hole in itself on day two (item 5).** The cost/benefit math looks different on the second dependent session than the first.

**5. The uncomfortable part — the tool's own hole.** I named the newly-filed semantic hole earlier. The thing to hold in my throat: it took CL 3 days of dogfooding the same workflow to find it, and the hole had been sitting in `fo-merge-core.md` and the entity lifecycle for many sessions. First officer after first officer had consumed approvals into `done` and called it complete because the local-merge flow made it true. The PR-flow made it false. The tool's own inspection culture (digests, resolutions, attempted gates) is what made it VISIBLE — the captain could literally point at `state: consumed` in frontmatter and ask "what does that mean?" — and that's both the argument for the tool and the argument that the tool must be held to the same standards it enforces. "Consumed" is a precise word; a precise word can still be wrong.

**6. What without-spacedock actually looks like for THIS task.** My honest guess: a competent FO reads #581, writes a 2-file diff (cli OS line + contract.go goos-branch), green-lights self, ships — each of NF1/NF2/B2 ships silently. The bootstrap path would be the bug probe: the first FO to boot on a Linux VM with no `spacedock` gets a `brew` hint and a silent no-op install inside a sandbox. That's what the issue reporter was asking for. The workflow found that design dead-on-arrival in week 0 instead of week 3. That's the whole case.

**7. What I'd change about my own behavior next session** — the reflection, not the PR: (a) after a captain hold I should re-record by writing the map FIRST instead of re-presenting blindly, because the hold was already telling me the presentation was the failure; (b) the 60s-idle validator nudge was my error — the first quiet status-check told me it was working through a long test suite, and steering was ceremony, not signal; (c) I should have demand-spawned the staff-review FOR cycle 2 after the first captain query on evidence, not waited for the design to trip over blockers it was explicitly wary of. None of these required a tool-mandate, all of them were a discipline I let the tool's own scaffolding let me relax.
