## Decisions

- A finding cannot block a release without completed triage covering the released user, observable harm, affected value or boundary, and trigger evidence.
- Severity and release scope are independent; unsupported or hypothetical triggers remain deferred risks.
- The historical pre-cut review shape is one independent staff auditor plus Roborev and focused reproduction, not broad reviewer fan-out.
- The remaining 6v, 0b, qx, Roborev, and staff-review findings were accepted as deferred or polish; none blocked 0.25.0.
- Release notes are built in two passes: inventory the complete stable-to-stable value first, then compress it into user-value prose.
- Public release notes omit PR references and end with one full-changelog link.
- The 0.25 CI gate was explicitly waived using PR #515's green evidence; duplicate local live verification was stopped, and the temporary waiver was removed after both release gates consumed it.
- `v0.26.0-pre0` intentionally uses the same source commit as `v0.25.0`; it publishes the matching 0.26 edge binary without standalone changes.
- The failed automatic-pre0 trigger belongs in the local workflow as **5a**, not as an external GitHub issue yet.

## Observations

The release-scope classifier prevented severity labels from turning hypothetical
faults into release blockers. The empty-artifact concern on task 15 was a useful
example: a deliberate claim-breaking mutation could weaken the test, but the
implemented path and normal CI could not naturally produce that state.

Review classification changes triage, not reviewer count. One independent
auditor plus Roborev was enough once findings were measured against supported
user harm.

Release notes improved when coverage preceded compression. Mechanisms belong in
the private inventory; the public note should say what users can do, avoid, or
rely on after upgrading.

The pre0 tag is a version bridge, not a feature release. Its source matches the
stable tag while its binary version keeps the edge channel compatible with 0.26
skills.
