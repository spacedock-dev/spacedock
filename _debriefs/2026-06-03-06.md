## Issues — Spacedock
- **Live tests are silently cacheable.** `go test -tags live` is cached by Go's test cache → a stale PASS can be replayed without launching the host (no model call, no real verification). Mitigation: `-count=1` baked into the live invocation (CI + README). Worth a framework note so every live lane carries it. (not filed — captain wrap-up)
- **FO `## Awaiting Completion` end-turn interacts badly with claude-code #55297** in `-p`+teams: ending the turn to wait triggers the per-turn shutdown reminder, which induces premature teardown. The `-p` override is a workaround, not a fix. (upstream: anthropics/claude-code#55297; not filed)

## Observations
- **Live verification earned its name a fifth time.** Every offline-green layer (marker grade, verdict gate, narrow gate, 3-stage fixture) was overturned only by a real live run. The win was running the live cycle *as the FO* myself, not trusting reported results.
- **A full multi-agent live lifecycle cannot be a deterministic hard gate.** Real FO + real ensign each make many non-deterministic decisions (drive, verdict, stage-report path, teardown); no prompt makes that deterministic. Bounded assertions (the teardown marker grade, the shared scenarios) are what can gate reliably — the captain's scoping reflects this.
- **Test-prompt hygiene matters:** the original `TestLiveEnsignCycle` coaching prompt ("dispatch an ensign for each stage; don't stop until terminal") both violated the canonical scenario-prompt rule and misframed the FO's job. Canonical neutral prompt + a generic `-p` shutdown-timing override is the right shape.
