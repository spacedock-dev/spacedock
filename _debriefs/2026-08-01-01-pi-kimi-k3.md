## Operator testimonial — spacedock as an agent operating multiple tasks

Requested by the captain as the session's qd testimonial. First-person, no varnish, from the seat of running z3's ceremony + 1w62 end-to-end + the dev-stamp filing + gates, reviews, and peer collisions in parallel.

**Genuinely load-bearing:**

1. **Durable state as the memory spine.** Six ensign dispatches, two rejected designs, three review rounds, and a history rewrite later — every thread state re-derived from entity files and gate records, not from context. Chat memory was the perishable part (the PR-draft text evaporates); the mod's extraction rules made it deterministically rebuildable. The pending-application semantics completes this: the parked 1w62 ceremony is resumable by any session with the right binary, because mid-flight is recorded authority, not a hopeful posture.
2. **Recorded authority.** Every decision is bytes — actor, decision, reason, bound briefing digest. Rejections had a legal route (revise + feedback-to + cycles) instead of improvised redos. "Whose call was that" is cheap: my own errors closed as `hold` under `agent:first-officer`, cleanly attributable.
3. **The dispatch-verify contract.** `dispatch build` → spawn → stage-report-as-gate converts "agent says done" into "bytes prove done" — the completeness guard caught a missing-evidence defect at exactly the right moment (the advance refusal). It bit twice and both bites were correct; a framework that disciplines the dispatcher too is the real test.
4. **Write-authority classes.** Three times the classifier stopped work I had no seat doing (stage-report edits, skills-product vs README-process, worker-owned bodies). For a multi-task agent the shortcut-a-small-edit temptation is constant; codified boundaries beat personal mood.

**Friction, honestly:**

1. **Ceremony tail cost for trivial corrections.** One mangled backtick = a `hold` record + fresh briefing attempt. One missing evidence line = an entire fresh ensign dispatch, because `subagent resume` rejected its own recovery descriptor (genuine pi-subagents bug: `recoveryDescriptor.acceptance` unsupported). Correct-but-heavy on high-stakes boundaries; on paper-cuts it reads as tax.
2. **Silent failure surfaces.** `state commit`'s push leg failed ~5 consecutive times with empty output — publication claims diverged from reality invisibly. Loud failure or a post-push verify would kill the class.
3. **Sharp mechanical edges.** `gate prepare` accepts attempts on ungated stages; the frozen-binding refusal doesn't name the resolution path; the completeness guard's error doesn't say *which* structural check failed. Each cost a debug round.
4. **Session-level attention is still the operator's.** Three ensigns + a reviewer + CI + captain-side edits needed my own ledger: worker identities, cohorts, armings. `status --boot` comes close but there's no "what am I waiting on" projection for an FO running multiple tasks — the biggest missing piece for this exact use case.
5. **The old consume semantics** was used twice today on live entities (z3, 1w62 attempt-4), each needing captain-shaped recovery had delivery failed. Fixed on the branch; watch the flip window until release.

**Net:** for one-shot small changes, overhead with good manners. For anything living across sessions, review rounds, or parallel entities, the framework caught certainty outpacing evidence four separate times today. The design instinct worth keeping: *make the awkward middle state real and recordable rather than fast and implicit* (the pending model), and institutionalizing "should this mechanism exist at all" (the ratchet lesson).

**Asked-for priorities if continued:** FO live-registry ("what am I waiting on") for multi-task operation; loud publication failures in `state commit`; evaluate driving the merge boundary with the candidate binary BEFORE the fix ships (the lesson I logged when I consumed under the old binary one authorized time too many).
