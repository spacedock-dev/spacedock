## Issues — Spacedock
- **e2e-gate is blind to re-run-to-green E2E runs** (the cut-blocker) — `cmd/spacedock-release/e2e_gate.go`'s `gh run list --status success` matches only `run_attempt 1` successes. The "re-run the flaked lane, never block the tag" guidance is silently incompatible: `gh run rerun --failed` produces a `run_attempt 2` run the gate can't see (`--status success -c SHA` → `[]`, while `-c SHA` alone returns it with `conclusion:success`). Recovered by dispatching a **fresh** run (`run_attempt 1`), never `rerun --failed`. Tracked as **`q3`** (recommend prioritizing — bites every flake-then-cut).
- **`dispatch build --team-name` foot-gun** — binary *is* team-mode-aware (`build.go:292` `mergedMode := !bareMode && host=="claude" && teamName==""`) but silently picks the legacy shape on `--team-name`; flags undocumented in `--help`, no warning. Tracked as **`0qt`**.
- **`status --ac-scan` skips `(VALUE)`-annotated ACs** — `**AC-1 (VALUE)**` isn't matched by the scan's `**AC-N**` matcher, so the *value* AC is invisible to the deterministic gate cross-check (caught manually for `3p`). Tracked as **`48g`**.

## Observations
- **The ideation spike disproved the `3p` filing premise** — the race is *structural*, not timing: the pump goroutine is created before `cmd.Start()`, so *every* `cmd.Process` read is unsynchronized regardless of signal timing. The existing tests are green only because the launcher runs as a **child process** whose `-race` report is swallowed (child `stderr`→`/dev/null`, `os.Exit` bypass, no `testing` harness). Real fix mechanism: drive `execHost.Launch` **in-process under the harness**. The spike discipline earned its keep before a line of fix was written.
- **The re-run/gate interaction is the durable lesson** — for a release cut, a flaked live lane must be cleared with a *fresh dispatch*, never `rerun --failed`, until `q3` lands.
- **The detached adversarial audit had teeth** — proved both `3p` test legs fail under claim-breaking edits (race detector catches reintroduced ordering; `exit==143` catches a silently-broken forward). The deterministic-merge call was validated: behavior unchanged, tagged-commit live E2E caught nothing new.
- **No post-stable preversion machinery** — after `0.23.0`, `main`'s manifests still read `0.23.0`; nothing advances the dev line to `0.24.0-pre.1`. The binary version self-derives from `git describe`; `next-publish.yml` only bumps the marketplace calendar key, not the semver. This is the `gr` gap (manual today).
