## Decisions
- **Marketplace `source.ref` is branch-local — the captain's catch.** Original AC-6 (flip `source.ref:main` on `next`) would have routed *edge* users' plugin to `main`. A real resolver probe (throwaway self-referential marketplace) proved the host clones the plugin from the manifest's `source.url@source.ref`, not the `@ref` checkout. Corrected: `next` keeps `source.ref:next`; `main` settles to `source.ref:main` via a `main`-only post-flip commit. AC-6 rewritten; `marketplace_manifest_test` relaxed to `∈{next,main}`; the channel-agreement guard's skip kept (it's branch-aware).
- **Settle before the tag**, not post-tag (step 8) — because `@main` resolves `main`'s branch *tip*, the `source.ref:main` settle landed right after the force-push so a fresh stable install can never resolve `@main → source.ref:next`. The tag points at the green-run commit, one behind the tip (like k6d's post-tag stamp).
- **AC-8: accept silent edge-retention.** A `next`-pinned 0.19.x user post-flip keeps pulling edge (no forced migration) — next-pinning is a deliberate edge opt-in and the edge channel stays live. No nudge fixture. Dev + Spacedock-state continue on `next`; `main` is stable-release-only.
- **`next` as its own release line = deferred (b)** (filed `twq`). The edge cask rides the stable tag for now; the edge plugin trails at next's own version (e.g. 0.19.9) — functionally correct (edge gets next content).
- **pj terminalized via a ship sentinel** (`pr=release:v0.20.0`) — it shipped via the release, not a code-branch PR, so the pr-merge guard is satisfied honestly without `--force`.
