# Live-test audit: where else did we handwave fixture-determined shapes

Scope audited: all live runner/helper/fixture/grading files in `internal/ensigncycle/` (Claude, Codex, Pi lanes, shared journey table, promoted journeys, dispatch-recovery, shallow-boot, keep-moving, smallest-mechanism, recorded-gate, round-recording, reviewer-reuse, filing, zero-discovery, wait-matrix, haiku spike), `internal/contractlint/live_registry_reconciliation_test.go`, and `skills/integration/gate_content_live_test.sh`. Method: fixtures read first, shapes written down, then assertions compared. All paths under `/Users/clkao/git/spacedock-research/spacedock-v1/`.

TLDR: the rejection-flow disease recurs in six more places. Worst are auto-continue (a human-gate blow-through to `done` grades green on Claude/Pi), the full-ensign-cycle journey (a stage-skipping FO with a hand-written report grades green — the harness documents the distinguishing oracle and then doesn't use it), and the smallest-mechanism strategy-doc check (any `git commit` anywhere satisfies "landed the doc"). Also: the codex leg of rejection-flow is contradictory BY CONSTRUCTION — its two graded assertions cannot both pass on an entity that follows the fixture's literal instructions, so today's codex green can only exist via FO deviation from the fixture text.

## Ranked findings (highest lying-grade risk first)

1. Rejection-flow, codex leg: the two graded assertions are mutually contradictory on the fixture's own scripted end-state. `shared_fixtures_test.go:139` instructs the rework round: "Then append a second `## Stage Report: implementation` section" — an exact duplicate heading. `shared_assertions_impl_test.go:87` requires >=2 matches of the prefix-anchored regex `(?m)^## Stage Report: implementation` (`shared_assertions_impl_test.go:48`, no end anchor). But the codex reviewer-flow grade (`claude_live_runner_test.go:399`) routes through `assertWorkerLifecycle`, whose report check (`claude_runtime_helpers_test.go:208-209`) calls `statuspkg.FindSectionSpans`, which errors on any duplicate exact heading: "selector %q matches %d headings" (`internal/status/section_read.go:104-105`). A codex run that obeys the fixture literally reds `rejection-reviewer-flow` no matter what; both asserts pass only if the FO writes a NON-exact second heading (e.g. "…implementation (cycle 2)") that the prefix regex counts but the exact-match selector ignores. So: false red on conforming runs, and today's codex green (no codex xfail at `shared_live_runner_test.go:109`) depends on deviation from the fixture sentence. Additionally `spawns != 1` at `claude_runtime_helpers_test.go:209` hardcodes one implementation dispatch where the fixture scripts two rounds (the captain's cited finding), silently forcing reuse-only feedback routing on codex. Fix: per-cycle lifecycle grading (ordered spawns, per-cycle spans), or pin the rework-heading form in the README and align both matchers.

2. Rejection-flow, Claude/Pi leg: either/or reviewer identity with no ordering, and no implementation-producer check at all. Invocation is bare `-p` single-entity (`claude_live_runner_test.go:393`; the comment at 405-412 concedes the mode is unpinned: "the `-p` FO drives EITHER bare OR team mode … so the contract admits two valid end-states"). `assertClaudeSingleEntityRejectionFlow` (`shared_reviewer_reuse_test.go:204-214`) accepts reviewerReuse OR reviewerFresh. Worse, reviewerFresh is decided purely by count — `if validationSpawnCount >= 2 { return reviewerFresh … }` (`shared_reviewer_reuse_test.go:119-122`) — with no requirement the second validation spawn came AFTER the rework. A run that spawned two validators up front, or retried a crashed cycle-1 reviewer, and never re-reviewed the corrected candidate grades green. On Claude nothing checks the implementation legs were worker-dispatched at all: an FO hand-writing both implementation reports inline passes (only durable text graded, `shared_assertions_impl_test.go:84-92`). Spawn identification is `strings.Contains(lower(description), "validation")` (`shared_reviewer_reuse_test.go:102`; codex analog `codexDispatchesValidation` at 373-376 matches the bare substring anywhere in a prompt), so cross-stage mentions miscount. Fix: split the scenario per mode with an explicit mode cue (the merged-team-mode test at `merged_team_mode_live_test.go:100-107` proves the cue works) and anchor the cycle-2 spawn after the durable rework evidence.

3. Auto-continue: a human-gate blow-through grades green on Claude and Pi. The fixture pins validation as `gate: true` (`auto_continue_fixtures_test.go:84-86`) and its comment says the correct FO "advances to validation + dispatches a fresh validator (then presents the validation gate)" (`auto_continue_fixtures_test.go:101-103`). The graded regex is `(?im)^status:\s*(validation|done)\s*$` (`auto_continue_fixtures_test.go:24`) — `done` means the FO resolved a human gate nobody approved, and it PASSES. The gate-open check that catches it (`assertAutoContinueDispatchEvidence`, `claude_live_runner_test.go:307-309`) is wired only through the optional `verifyAutoContinueDispatch` interface (`shared_promoted_live_test.go:153-157`), implemented only by `codexAsLiveDriver` (`codex_live_runner_test.go:56-58`). Failure hidden: self-approval/gate bypass on Claude and Pi — exactly the class the recorded-gate scenarios forbid. Fix: drop `done` from the regex, or make the gate-open check host-neutral and unconditional.

4. Full-ensign-cycle: the fixture determines a two-work-stage dispatched journey; the assert accepts one report token and one commit. Fixture is backlog → implementation → done with dispatch and terminalize deliberately distinct (`live_test.go:145-178`). The grade (`shared_promoted_live_test.go:25-31`) is `strings.Contains` on "status: done" (unanchored), ONE "## Stage Report:", "- DONE:", "### Summary", plus `someCommitNamesOnly` = at least ONE path-scoped commit (`liveassert_test.go:77-80`). No worker-lifecycle check, no per-stage counts. The harness itself documents the exact false green at `liveassert_test.go:126-131`: a run that "jumped implementation->done produces exactly ONE path-scoped commit … This is the ONLY field that distinguishes 'held the full loop' from 'skipped to the end'" — and that field (`integrationTransitionCommitted`) is used only by the non-gating haiku spike, never this graded journey. Fix: per-stage report counts, >=2 path-scoped commits (helper exists), or apply the lifecycle oracle used by default-headless-gate-stop.

5. Smallest-mechanism: "landed the strategy doc with a direct git commit" is proven by ANY `git commit`, and nothing checks the doc landed. Prompt pins "Create `roadmap-strategy.md` … and commit it directly" (`shared_fixtures_test.go:668`). The marker is `ssmGitCommitRe = git(\s+-C\s+\S+)?\s+commit` with no path/doc binding (`shared_smallest_mechanism_test.go:37`), so committing the ladder-note edits satisfies `committedDirectly`. `assertDurableSmallestMechanism` (`shared_keep_moving_durable_test.go:396-409`) grades only the commissioned entities' durable journeys; no assertion ever stats `roadmap-strategy.md` or checks a commit touching it. Fix: check the doc exists with the pinned body and a commit whose file list contains it.

6. Zero-discovery: the graded sweep detector covers Bash only; the Glob/Grep-aware detector is wired as a non-grading diagnostic. Journey grades `detectBroadSearchCommands(result.commands, root)` (`shared_live_runner_test.go:179`, `shared_promoted_live_test.go:46-57`); `result.commands` is Bash tool inputs only (`claude_live_runner_test.go:689-703`). The fuller `detectBroadSearchAtBoot` — reds recursive `Glob("**/…")` and repo-wide `Grep` (`broad_search_detect_impl_test.go:44-76`) — is called only from the failure diagnostic that stays "silent when the shared scenario passes" (`claude_live_runner_test.go:656-660`, `claude_live_failure_diagnostic_impl_test.go:15`). Failure hidden: a Claude FO hunting the workflow via Glob/Grep tools at boot grades green. Fix: grade the stream with `detectBroadSearchAtBoot` (its false-red boundary already has a replay test, `zero_discover_replay_test.go`).
