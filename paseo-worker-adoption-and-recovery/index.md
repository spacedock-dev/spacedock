Persist the Paseo worker handle and retry ledger in a temporary local lease file (`<git-common-dir>/spacedock-paseo-leases/<slug>.yaml`, superseded by future lease work `79` / `entity-session-claim-lease`) with zero entity-markdown pollution so a restarted or compacted first officer adopts a live worker instead of double-dispatching, and handle wait timeouts, lost create receipts, dead workers, and duplicate completion events with deterministic single-retry-then-hold recovery isolated per entity.

## Problem

With `paseo-dispatch-backend` (`936`) alone, a Paseo-hosted first officer (FO) that restarts, compacts, or crashes mid-stage has no durable local record of the in-flight Paseo agent ID, workspace ID, or pre-dispatch state revision. On resume, a fresh FO risks spawning a second worker on the same stamped worktree/branch or mistaking a prior stage report for new completion evidence. Similarly, Paseo's `paseo wait --timeout` exits `0` with JSON `status=timeout` during normal live progress, a dropped `paseo run --no-wait` call can leave an unrecorded worker running on the daemon (lost create receipt), and an ended worker with a missing/incomplete report or a duplicate finish event needs exact, zero-ambiguity recovery rules so one failing task never wedges unrelated tasks. At the same time, transient runtime worker handles and dispatch-retry ledgers must NOT pollute durable entity markdown files or entity Git history before proper leases (`79`) are designed.

## Proposed approach

Extend `skills/first-officer/references/paseo-fo-dispatch.md` (shipped by `936`) with the temporary local lease file (`<git-common-dir>/spacedock-paseo-leases/<slug>.yaml`), deterministic restart adoption and lost-create-receipt reconciliation, and the 11-row recovery matrix (with zero edits to `skills/first-officer/references/fo-write-core.md`, `skills/first-officer/references/first-officer-shared-core.md`, or `internal/status/`); update `docs/runtime-live-ci.md` (STE, no hardcoded model literals); and prove restart adoption plus zero entity pollution end-to-end against a real isolated `paseo` daemon in `internal/ensigncycle/paseo_adoption_live_test.go` (`TestLivePaseoAdoptionSmoke`), consuming `936`'s package-private `internal/ensigncycle/paseo_live_helpers_test.go` seam and `internal/release/live_models.txt` SSOT with zero edits to `936`'s test files. No new `spacedock` CLI subcommands, no uncalled production Go simulator, and no fake ACP stub servers are introduced.

### 1. Temporary local worker-lease schema (`<git-common-dir>/spacedock-paseo-leases/<slug>.yaml`)

Store one FO-owned temporary local YAML lease file at `<git-common-dir>/spacedock-paseo-leases/<slug>.yaml`, where `<git-common-dir>` is resolved via `git -C {workflow_dir} rev-parse --path-format=absolute --git-common-dir` (or by canonicalizing relative output from `git -C {workflow_dir} rev-parse --git-common-dir` against `{workflow_dir}`). Explicitly document this format as a temporary local lease superseded by future lease work (`79` / `entity-session-claim-lease`).

**Creation, atomicity, and durability boundary:**
- Owned exclusively by the FO (never edited by ensigns). Create the directory with `mkdir -p "$lease_dir"` and write atomically via temp file + `mv -f` (`"${lease_file}.tmp.$$"` -> `"$lease_file"`).
- **Zero entity-file writes & zero Git pollution:** NEVER commit lease files to Git and NEVER write worker handles (`## Paseo Worker`) or dispatch-retry ledgers (`### Dispatch Retries`) into entity markdown (`index.md` / `<slug>.md`). Placing leases under `<git-common-dir>/spacedock-paseo-leases/` never dirties `git status --porcelain` in either the code checkout or `.spacedock-state` and works identically in split-root and single-root repos.
- Updated ONLY at launch/adoption (`state: running`), retry append, and terminal attempt outcome (`archived`, `superseded`, or `held`).

**Exact YAML schema (lean runtime fields + `retries: []`, aligned with `936`'s `«worker-identity»`):**

**Field contract (aligned with Paseo 0.17.1 `inspect` PascalCase / `ls` camelCase JSON and `936`'s shared label contract):**
- `agent_id`: Paseo `agentId` (`inspect.Id` / `ls[].id`) from `paseo run --no-wait` or recovered via `paseo ls`.
- `workspace_id`: Paseo `workspaceId` from Verb 1 find-or-create (`paseo workspace ls --json` -> `paseo workspace create`).
- `server_id`: daemon server ID from `paseo status --json` / `paseo.parent-server-id` label; `"local"` when a local isolated daemon omits a server ID.
- `stage`: entity `status:` at dispatch time.
- `epoch`: exact `spacedock.epoch` label passed to `paseo run` — deterministically `{worker_base}-c{cycle}-a{attempt}` (lowercase `[a-z0-9-]`, unique per `(entity, stage, cycle, attempt)`, recomputable cold from durable entity state + local lease retries).
- `cwd`: resolved physical working directory (`filepath.EvalSymlinks` / `pwd -P`) adopted by Verb 1 (matches `inspect.Cwd`; relative worktree path remains in `frontmatter.worktree`).
- `pre_dispatch_state_rev`: `git -C {state_checkout} rev-parse HEAD` captured immediately AFTER `dispatch build --stamp` and BEFORE `paseo run --no-wait` (prevents pre-existing or prior-cycle stage reports from falsely satisfying verification).
- `requested` (`provider`, `mode`, `thinking`): exact `--provider <provider>/<model>`, `--mode` (`""` if omitted), and `--thinking` (`""` if omitted) passed to `paseo run`.
- `returned` (`provider`, `mode`, `thinking`): effective values returned by `paseo inspect` (`<Provider>/<Model>` or `<Provider>`, `Mode`, `Thinking`; explicitly capturing discrepancies).
- `state`: closed 4-value enum:
  - `running` — worker is live (dispatched or adopted) and awaiting completion.
  - `archived` — durable Git proof passed the completion gate and the worker was archived (`paseo archive <agent_id> --json`; `inspect.Archived == true`); terminal clean state for this attempt.
  - `superseded` — worker failed/ended without valid completion and was archived before launching a replacement.
  - `held` — entity exhausted its single retry or hit an unresolvable ambiguity/permission block; only this entity is held.
- `hold_reason` (optional): non-empty concrete one-line diagnostic present only when `state == held`.
- `retries`: list of `{ stage, cycle, cause }` entries (`cause` in `spawn-error | ended-no-report | incomplete-report`), initialized to `retries: []` and stored exclusively in the local lease YAML (distinct from `### Feedback Cycles`, never written to entity markdown).

**Shared Paseo label contract (frozen identically across `936` and `x9m`, preserving `internal/dispatch/names.go` <= 56-char budget):**
- `spacedock.worker`: **ALWAYS invariant `{worker_base}`** (canonical `envelope.name` from `spacedock dispatch build --host paseo` or read-only `spacedock dispatch name`). NEVER append `-retry` or `-cycleN-retry` to `spacedock.worker` — keeping `spacedock.worker` invariant ensures `paseo ls --global --label "spacedock.worker={worker_base}" --json` enumerates **every** attempt (initial, rework, and retry) for `(entity, stage)` and stays within `names.go`'s suffix cap.
- `spacedock.epoch`: **`{worker_base}-c{cycle}-a{attempt}`**, where `cycle = 1 + count(prior feedback cycles for stage in ### Feedback Cycles)` and `attempt = 1` initially or `2` on the single allowed retry (`{worker_base}-c1-a1` for v1 fresh dispatch in `936`, `{worker_base}-c1-a2` on cycle-1 retry, `{worker_base}-c2-a1` on feedback cycle 2).

### 2. Deterministic FO restart adoption & lost-create-receipt reconciliation

**Shared Paseo 0.17.1 CLI invariants (aligned with `936`):**
- **Find-or-create workspace (Verb 1):** Before spawning (especially on retry, feedback rework, or non-worktree stages), call `paseo workspace ls --json` and reuse any active workspace whose canonical `cwd` equals `$code_cwd`; call `paseo workspace create --isolation local --path "$code_cwd" ... --json` only when no matching workspace exists (Paseo `workspace create` is not idempotent and leaks duplicate workspaces on repeated calls).
- **Stdout-only JSON parsing:** `paseo run --workspace ... --json` prints non-JSON `Using workspace wks_...` to stderr even on exit `0`. Always parse stdout only (`2>/dev/null` when piping to `jq`, or separate stdout/stderr buffers in Go via `(*paseoDaemon).runJSON` — never `CombinedOutput`).

On boot, compaction resume, or `«dispatch.next-action»()` for an entity in active stage `S = entity.status`:

1. **Step 0 — Derive expected identity from durable entity state + local lease:**
   - Read entity frontmatter (`status`, `started`, `worktree`) and `### Feedback Cycles` (read-only), plus the local lease `<git-common-dir>/spacedock-paseo-leases/<slug>.yaml` if present.
   - Run read-only `spacedock dispatch name --workflow-dir {workflow_dir} --entity-path {entity_path} --stage {S}` to get invariant `worker_base`.
   - Compute `cycle = 1 + count(feedback cycles for S)`, `retries_done = count(lease.retries entries matching (S, cycle))`, `attempt = 1 + retries_done`.
   - Compute `expected_epoch = {worker_base}-c{cycle}-a{attempt}` and canonical physical `expected_cwd` (`filepath.EvalSymlinks` / `pwd -P` of `worktree` if set, else repo root).
2. **Step 1 — Check terminal/held/completed state first:**
   - If the local lease matches `(stage == S, epoch == expected_epoch)` and `state == held`: skip this entity (remain held) and continue unrelated entities.
   - If the local lease matches `(stage == S, epoch == expected_epoch)` and `state == archived`: if `HasValidNewReport` is true, resume completion advance (`merge guard` / `gate prepare` / advance to next stage) with zero new spawn; otherwise proceed to Step 2.
3. **Step 2 — Primary lookup via recorded `agent_id` (local lease matches `(stage == S, epoch == expected_epoch)` and `state == running`):**
   - Run `paseo inspect <lease.agent_id> --json` and route through the Recovery Matrix below (`AGENT_NOT_FOUND` counts as ended).
4. **Step 3 — Lost-create-receipt reconciliation (no matching local lease for `(S, expected_epoch)`, empty `agent_id`, or `paseo run --no-wait` failed/dropped without returning a receipt):**
   - Query labels in exact priority order BEFORE ever calling `paseo run --no-wait`:
     1. **Epoch lookup:** run `paseo ls --global --label "spacedock.epoch={expected_epoch}" --json` **without `--all`** first (excluding archived agents server/CLI-side); retry with `--all` ONLY if that returns `[]`.
     2. **Invariant worker-label fallback (only if step 3.1 returns `[]`):** run `paseo ls --global --label "spacedock.worker={worker_base}" --json` **without `--all`** first, retrying with `--all` ONLY if empty.
     3. **Inspect-based candidate filtering (NEVER filter on `ls[].cwd`, `ls[].created`, or `ls[].status` for archival):** call `paseo inspect <candidate.id> --json` on each candidate and match ONLY rows where:
        - `inspect.Cwd == expected_cwd` (unshortened physical path), AND
        - (when `frontmatter.started` is non-empty) ISO-8601 `inspect.CreatedAt >= frontmatter.started`, AND
        - prefer `inspect.Archived == false` (keep archived matches only if no non-archived candidate exists and `HasValidNewReport` may already be satisfied).
   - Branch on filtered candidate count:
     - **Exactly 1 match `W`:** atomically backfill the local lease from `inspect` (using the `dispatch: {slug} entering {S}` state commit SHA as `pre_dispatch_state_rev` when missing, preserving `retries` or initializing `retries: []`); adopt `W` and enter the Recovery Matrix with **0 retries spent** and **0 duplicate spawn**.
     - **> 1 active (`inspect.Archived == false && inspect.Status != "closed"`) matches:** ambiguous roster — atomically update local lease `state: held`, `hold_reason: "ambiguous-active-workers: <id1>,<id2>"`, surface to captain, do NOT spawn another worker, do NOT kill unowned agents, continue unrelated entities.
     - **0 matches:** if triggered by ordinary boot/engage, proceed to `SpawnFresh` (using Verb 1 find-or-create); if triggered by a failed `paseo run --no-wait`, classify as confirmed `spawn-error` and enter Recovery Matrix rows 8–9.

### 3. Exact recovery matrix (zero day-1 ambiguities)

Sole decision owner for all `wait`, `inspect`, `archive`, and adoption outcomes (Verb 3 observes and routes all `timeout`/`permission`/`idle`/`error`/`AGENT_NOT_FOUND` statuses through this matrix). All recovery actions are isolated per entity; unrelated entities remain unaffected.

**Durable Git verification predicate `HasValidNewReport(entity, stage, pre_dispatch_state_rev)`** — all four must hold:
1. `git -C {state_checkout} rev-list {pre_dispatch_state_rev}..HEAD -- {entity_rel}` is non-empty and the committed entity carries a new `## Stage Report: {stage}` passing `spacedock status --read <entity> --stage {stage} --checklist --json` (every retained checklist item accounted for, non-empty evidence lines, non-empty `### Summary`, no `FAILED` items except feedback-review findings).
2. `git -C {state_checkout} status --porcelain -- {entity_rel}` is empty.
3. For worktree stages (`worktree != ""`), the code worktree is on the expected task branch with clean `git -C {worktree} status --porcelain`.
