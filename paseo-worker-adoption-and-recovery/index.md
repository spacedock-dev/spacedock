Reconcile Paseo worker state purely from the three pre-existing sources of truth — entity + `.spacedock-state` Git history, code worktree Git state, and Paseo daemon labels (`spacedock.worker`, `spacedock.epoch`) + `paseo inspect` — with zero sidecar/lease files and zero entity-markdown pollution, so a restarted or compacted first officer adopts a live worker instead of double-dispatching and handles wait timeouts, lost create receipts, dead workers, and duplicate completion events with deterministic single-retry-then-hold recovery isolated per entity.

## Problem

With `paseo-dispatch-backend` (`936`, merged to `main` in `3d134b255`) alone, `skills/first-officer/SKILL.md:38` loads `paseo-fo-dispatch.md` only at first dispatch (not on resume), `paseo-fo-dispatch.md` hardcodes `-c1-a1` epochs and an unconditional Verb 3 `error -> hold` rule, and there is no unified roster-reconciliation or recovery contract. On restart, compaction, or crash mid-stage, a fresh Paseo-hosted first officer (FO) risks spawning a duplicate worker on the same stamped worktree/branch or failing to adopt an in-flight worker. Similarly, Paseo's `paseo wait --timeout` exits `0` with JSON `status=timeout` during normal live progress, a dropped `paseo run --no-wait` call can leave an unrecorded worker running on the daemon (lost create receipt), and an ended worker with a missing/incomplete report or a duplicate finish event needs exact, zero-ambiguity recovery rules so one failing task never wedges unrelated tasks. Per Captain's architectural ruling, transient worker handles and retry counts must NOT be written to sidecar lease files or entity markdown before durable leases (`79`) are designed.

## Proposed approach

Extend `skills/first-officer/SKILL.md:38` (1 line) and `skills/first-officer/references/paseo-fo-dispatch.md` (shipped by `936`) with pure 3-source-of-truth roster reconciliation and a compact 8-row recovery matrix (zero sidecar/lease files, zero entity-body `## Paseo Worker` / `### Dispatch Retries` writes, and zero edits to `fo-write-core.md`, `first-officer-shared-core.md`, `internal/status/`, `internal/cli/`, or any `936` Go/workflow/test file vs `origin/main` `3d134b255`); update `docs/runtime-live-ci.md` (STE, no hardcoded model literals); and prove restart adoption plus zero lease-file / zero entity-file pollution end-to-end against a real isolated `paseo` daemon in `internal/ensigncycle/paseo_adoption_live_test.go` (`TestLivePaseoAdoptionSmoke`), consuming `936`'s package-private `internal/ensigncycle/paseo_live_helpers_test.go` seam and `internal/release/live_models.txt` SSOT with zero YAML lease parsing and zero edits to `936`'s test files.

### 1. Three pre-existing sources of truth (zero lease files, zero entity-body worker writes)

FOs reconcile worker state strictly from three pre-existing sources of truth without inventing any sidecar lease file (`<git-common-dir>/spacedock-paseo-leases/...`) and without writing `## Paseo Worker` or `### Dispatch Retries` into entity markdown:

1. **Entity + `.spacedock-state` Git history:** `frontmatter.status`, `frontmatter.started`, `frontmatter.worktree`, `### Feedback Cycles`, and stage-entry baseline commit SHA (`dispatch: {slug} entering {S}` or backward-route commit on `{entity_rel}`).
2. **Code worktree Git state:** expected task branch and clean `git status --porcelain`.
3. **Paseo daemon labels + `paseo inspect`:**
   - `spacedock.worker` = invariant `{worker_base}` (`envelope.name` from `spacedock dispatch build --host paseo` or read-only `spacedock dispatch name`, always <= 56 chars; never append `-retry` or `-cycleN`).
   - `spacedock.epoch` = `{worker_base}-c{cycle}-a{attempt}`, where `cycle = 1 + count(### Feedback Cycles entries for stage S)` and `attempt` is `1` initially (`a1`) or `2` on the single allowed retry (`a2`).

### 2. Unified `## Roster Reconciliation`

On boot, compaction resume, `«dispatch.next-action»()`, or after a failed/dropped `paseo run --no-wait` for an entity in active stage `S = entity.status`:

1. **Derive `(worker_base, cycle, expected_cwd, baseline_rev)` from entity + `.spacedock-state` Git log:**
   - Read frontmatter (`status`, `started`, `worktree`) and `### Feedback Cycles` (read-only).
   - Run read-only `${SPACEDOCK_BIN:-spacedock} dispatch name --workflow-dir {workflow_dir} --entity-path {entity_path} --stage {S}` for invariant `worker_base`.
   - Compute `cycle = 1 + count(### Feedback Cycles entries for S)` and canonical physical `expected_cwd` (`realpath` / `pwd -P` of `worktree` if non-empty, else repo root).
   - Derive `baseline_rev` from `.spacedock-state` Git log on `{entity_rel}`: the latest `dispatch: {slug} entering {S}` (or backward-route / stage-entry) commit SHA for `(S, cycle)`.
2. **Query and inspect-filter Paseo daemon rows:**
   - Run `paseo ls --global --all --label "spacedock.worker={worker_base}" --json` and keep rows whose `labels["spacedock.epoch"]` matches `{worker_base}-c{cycle}-a*`.
   - Filter via `paseo inspect <id> --json` (never filter on `ls[].cwd`, `ls[].created`, or `ls[].status` for archival), keeping ONLY rows where `inspect.Cwd == expected_cwd` AND (`frontmatter.started` is empty or ISO-8601 `inspect.CreatedAt >= frontmatter.started`).
3. **Partition and route:**
   - Partition filtered rows into `running` (`!inspect.Archived && inspect.Status == "running"`) and `ended` (`inspect.Archived || inspect.Status != "running"`), and note whether an `a2` row exists for `(S, cycle)` (retry spent).
   - If 0 filtered rows exist on boot/engage: advance if `HasValidNewReport` already holds, else `SpawnFresh` (`a1`). If 0 rows exist after a failed `paseo run --no-wait`, route to Row 8 (`spawn-error`). Otherwise route directly through `## Recovery Matrix`.

### 3. Compact 8-row `## Recovery Matrix`

Sole decision owner for all `wait`, `inspect`, `archive`, lost-create-receipt, and resume outcomes (Verb 3 observes and routes all `timeout`/`permission`/`idle`/`error`/`AGENT_NOT_FOUND` statuses through this matrix). Every recovery decision is strictly isolated per entity (unrelated entities remain unaffected), and every archival obeys Verb 5's cascade-archive guard (never archive `$PASEO_AGENT_ID` or an FO while any child runs).

**`HasValidNewReport(entity, stage, baseline_rev)`** — all three Git predicates must hold:
1. `git -C {state_checkout} rev-list {baseline_rev}..HEAD -- {entity_rel}` is non-empty and the committed entity carries a new `## Stage Report: {stage}` passing `${SPACEDOCK_BIN:-spacedock} status --read <entity> --stage {stage} --checklist --json` with non-empty evidence, non-empty `### Summary`, and no `FAILED` items except feedback-review findings.
2. `git -C {state_checkout} status --porcelain -- {entity_rel}` is empty.
3. For worktree stages (`worktree != ""`), the code worktree is on the expected task branch with clean `git -C {worktree} status --porcelain`.

| Row | Observed State | Decision & Action |
|---|---|---|
| 1 | `wait` `status=timeout` + `inspect` `Status=running` & `PendingPermissions=[]` | `ContinueWait`: re-issue `paseo wait <id> --timeout 300 --json` (0 retries). |
| 2 | `wait` `status=permission` OR `inspect.PendingPermissions != []` (precedes Row 3 even when `Status=running`) | `HoldEntity`: keep worker live, stop & surface to captain (0 retries). |
| 3 | 1 running worker (on resume or dropped `run --no-wait` receipt) with `PendingPermissions=[]` | `AdoptRunning`: enter `paseo wait <id> --timeout 300 --json` loop (0 duplicate spawns, 0 retries). |
| 4 | 0 running + `HasValidNewReport == true` | `VerifyAndArchive`: idempotent `paseo archive <id> --json` for any unarchived matched worker (treat `AGENT_ALREADY_ARCHIVED` and `AGENT_NOT_FOUND` as success) -> advance / `gate prepare` / `merge guard`. |
| 5 | 0 running + `HasValidNewReport == false` + `a1` only (no `a2`) | `ArchiveAndRetry`: idempotent `paseo archive <id> --json` for unarchived `a1` -> reuse workspace (Verb 1) & spawn ONE replacement `a2` (`spacedock.worker={worker_base}`, `spacedock.epoch={worker_base}-c{cycle}-a2`, no `--stamp`, WIP check note). |
| 6 | 0 running + `HasValidNewReport == false` + `a2` already exists | `RetryExhausted`: idempotent `paseo archive <id> --json` for unarchived `a2` -> stop & surface to captain (unrelated entities unaffected). |
| 7 | `> 1` running workers | `AmbiguousRoster`: stop & surface to captain; never spawn or kill unowned agents. |
| 8 | `spawn-error` (`paseo run --no-wait` exits 1 and Roster Reconciliation confirms 0 agents created for `(S, cycle, attempt)`) | If on `a1`, retry ONCE in-turn with `spacedock.epoch={worker_base}-c{cycle}-a2` (reusing workspace via Verb 1, no `--stamp`); if already on `a2`, stop & surface to captain. |

Late/duplicate completion for an already-advanced entity (`entity.status != S`) or an already-archived worker with no pending advance is a strict no-op.
