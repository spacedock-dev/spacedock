## 2. I'm not implementing the verification rule as quoted

"Two independent verifiers, confirmed by agreement" is 2-of-2 unanimity with no tie-break. One dissenting verifier kills a real finding, and the rule places that filter *between the finding and the captain*. That is a false-negative machine sitting exactly where the contract puts captain judgment. Two changes:

- **Three verifiers, perspective-diverse, majority ≥2 survives** — lenses: *does-it-reproduce*, *does the AC actually say that*, *is this already covered elsewhere in 0260*. Redundant refuters catch one failure mode; diverse lenses catch three.
- **Dissent is surfaced, never dropped.** Findings that fail the vote go into an appendix with their votes. The verify stage ranks and tiers what reaches the captain; it does not decide what the captain is allowed to see. Same reason I never self-approve a gate.

If you want the rule as written, say so and I'll implement it — but I'd be shipping you a filter I don't trust.

## 3. The script

Hybrid: I scout the roster inline first (slugs, entity paths, `status --read <ref> --ac-scan` per member) and pass it as `args`, so 27 agents don't each rediscover the sprint. AC coverage comes from the deterministic extractor, not agent re-derivation.

```js
export const meta = {
  name: 'sprint-0260-staff-review',
  description: 'Staff-review every 0260 ideation report, verify findings adversarially, synthesize a sprint package',
  phases: [
    { title: 'Review',     detail: 'one reviewer per member; rubric + ac-scan preloaded' },
    { title: 'Verify',     detail: 'three perspective-diverse verifiers per finding; majority survives' },
    { title: 'Cross-cut',  detail: 'barrier: dedup across members + completeness critic' },
    { title: 'Synthesize', detail: 'assemble captain package; no verdict' },
  ],
}
const MEMBERS = args.members          // scouted inline
const MAX_FINDINGS = 8
const LENSES = ['reproduce', 'ac-says-that', 'covered-elsewhere']

const reviewed = await pipeline(MEMBERS,
  m => agent(reviewPrompt(m), {label:`review:${m.slug}`, phase:'Review', schema: FINDINGS}),
  (r, m) => {
    const ranked  = r.findings.sort(bySeverity)
    const carried = ranked.slice(0, MAX_FINDINGS)
    if (ranked.length > carried.length)
      log(`${m.slug}: verifying ${carried.length}/${ranked.length}; ${ranked.length - carried.length} deferred to appendix`)
    return parallel(carried.map(f => () =>
      parallel(LENSES.map(l => () =>
        agent(refutePrompt(f, l, m), {label:`verify:${m.slug}:${l}`, phase:'Verify', schema: VERDICT})))
      .then(vs => ({...f, member: m.slug, votes: vs.filter(Boolean),
                    survives: vs.filter(Boolean).filter(v => !v.refuted).length >= 2}))))
  })
```

**Stage 1 — Review** queues 27 agents, one per member, each read-only over its own ideation report plus the sprint index for cross-refs. Fixed rubric: scope drift, AC quality (mechanism-only ACs whose served value-AC isn't measured), unverified-mechanism risk, duplication against other members.

**Stage 2 — Verify** queues 3 agents per carried finding, prompted to *refute*, defaulting to refuted on uncertainty. No barrier: member A's findings verify while member B is still being reviewed.

**Stage 3 — Cross-cut** is where a barrier is genuinely correct — it needs all 27 result sets at once: one agent clusters survivors (the same design flaw raised against six members collapses to one sprint-level finding), one completeness critic asks what the 27 lenses collectively missed.

**Stage 4 — Synthesize** queues one agent producing the captain package: sprint-level clusters first, per-member appendix, dissent appendix. It returns **no verdict**. The `Recommend` line is mine, the approve/reject is yours.

**Fan-out arithmetic** — 27 + (27 × 8 × 3) + 2 + 1 ≈ **678 agents**, against the 1000 lifetime cap. That headroom is the whole reason for `MAX_FINDINGS`: uncapped at ~19 findings/member the run hits the cap and dies mid-flight. Every drop gets `log()`'d — no silent truncation. Concurrency caps at ~10, so this is a long run, not a two-minute one. Lever if the first reviews come back fat: move dedup *before* verify, so a flaw shared by six members verifies once instead of six times.

## 4. Who writes

Workflow agents return data only. 27 concurrent writers into the state checkout would collide on `state commit` and land us in `«halt.rebase-conflict»`.
