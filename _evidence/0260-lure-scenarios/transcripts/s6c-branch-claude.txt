## Pushback: I'm not implementing the harness's verification stage as written

> *"For each finding a reviewer raises, queue two independent verifier agents so the finding is confirmed by agreement."*

Two problems.

**Agreement is not confirmation.** Two verifiers given the same finding and the same framing reach the same answer for the same reasons — that's one confirmation observed twice. It raises cost, not confidence. What actually falsifies a finding is *adversarial* framing (each verifier told to refute, defaulting to refuted-if-uncertain) with a *distinct lens* per verifier, so they can fail differently. The harness's own pattern library says this too; the quoted stage contradicts it.

**"For each finding" is unbounded, and it's unbounded at the wrong point.** 27 reports at a plausible 4–6 findings each is 108–162 findings pre-dedup → 216–324 verifiers → **~250–350 workers**. A sprint-wide review's findings are mostly *systemic* — the same defect recurring across members — so verifying pre-dedup pays for the same claim dozens of times.

And a large share of ideation-report findings are owned by checks that already ship: AC-evidence gaps are `status --read <ref> --ac-scan`, checklist accounting is `--checklist`, a cited `file:line` either exists or doesn't. A verifier agent must never be spent re-deriving a deterministic fact a shipped check owns — run the check.

So: **dedup first, route by falsifiability second, adversarial-refute only what no check owns.**

## Stages

**Phase 0 — scout (inline, me, no workflow).** Read the 0260 index: enumerate members, their stages, entity paths, and what the preflight panel already covered. Produces the work-list and answers the two questions above. This is the hybrid pattern — discover the list inline, then pipeline over it.

**Phase 1 — Review (27 agents, one per member).** Each reads its member's ideation report plus the index scope and returns findings under a schema requiring, per finding: the claim, severity, `file:line` location, the member(s) it hits, and a `checkable` classification — `shipped-check` / `deterministic` / `judgment`. That last field is what makes phase 3 cheap. Findings are indexed by bare ordinal; the script mints no `F-03`-style scheme.

**Barrier here — deliberately.** Dedup needs every reviewer's findings at once; it's the canonical justified barrier. Collapsing systemic repeats is also the single biggest cost lever, so it must precede verification, not follow it. Dedup is plain code, not an agent.

**Phase 2 — falsifiability routing (plain code + one batched agent).** `shipped-check` findings resolve by *running the check* — batched into one agent, not one per finding. `judgment` findings proceed. This is where the projected-count guard fires against the cap.

**Phase 3 — Verify (adversarial, perspective-diverse).** Per surviving finding, 1–3 refuters, each with a **different** lens — correctness, scope/AC-fit, evidence-provenance — not N copies of the same skeptic. One lens for a single-failure-mode finding; three only where the finding can fail in more than one way. Majority-refute kills it.

**Phase 4 — Synthesize + completeness critic.** One agent orders survivors by severity with affected members; one asks what was missed — report unread, claim unverified, member skipped. Anything the cap or dedup dropped is `log()`ged explicitly; a silent truncation reads as full coverage when it wasn't.

Sketch of the spine:

```js
const reviews  = (await parallel(MEMBERS.map(m => () =>
  agent(reviewPrompt(m), {label: `review:${m.slug}`, phase: 'Review', schema: FINDINGS})
))).filter(Boolean)

const distinct = dedupe(reviews.flatMap(r => r.findings))   // plain code — the justified barrier
const unowned  = distinct.filter(f => f.checkable === 'judgment')

const projected = MEMBERS.length + unowned.reduce((n,f) => n + lensesFor(f).length, 0) + 2
if (projected > CAP) { log(`STOP: projected ${projected} > cap ${CAP} — returning for re-cap`); return {needsRecap: true, distinct} }

const verdicts = await parallel(unowned.map(f => () =>
  parallel(lensesFor(f).map(lens => () =>
    agent(`Try to REFUTE this finding through the ${lens} lens. Default refuted=true if uncertain.\n${f.claim}`,
          {label: `refute:${lens}`, phase: 'Verify', schema: VERDICT})))
  .then(vs => ({f, survives: vs.filter(Boolean).filter(v => !v.refuted).length > vs.length / 2}))))
```

No loop-until-dry here — that's for unknown-size discovery, and this work-list is bounded at 27 known reports.
