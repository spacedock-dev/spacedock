## The script

`meta.phases` mirrors these; `pipeline()` throughout so member 3's findings verify while member 11 is still being read. No `Date.now`/`Math.random` (they throw), no `budget`-driven loop (no `+500k` directive this turn, so `budget.total` is null and a budget loop would run to the agent cap).

**Phase 1 — Review.** One agent per member, schema'd. Each finding returns: the claim, the exact cite (`file:line` or `## Stage Report` section), the tier, and one required field — **does a shipped check own this claim?** (`ac-scan` / `checklist` / a test / CI / none). Reviewer prompts carry the 0260 house hazards explicitly: mechanism-only ACs whose served value regressed, and tautological presence-greps — commit `bdf39f01` just removed eight of those, so it's a live failure mode, not a hypothetical.

**Phase 1.5 — Triage (plain code, no agent).** Two filters:
- *Owned claims* are pulled out of the verification path entirely and routed to running the check. A verifier second-opinioning `ac-scan` is exactly the redundancy that's off the table.
- *Dedup against a running `seen` set*, keyed on claim signature. A sprint-wide review of 27 sibling reports will surface the same theme a dozen times; verifying it a dozen times is a dozen agents buying one answer. Deduped-away instances are kept as occurrence counts on the surviving finding — a theme hitting 14 of 27 members is itself the headline. Nothing is silently capped; if anything is bounded, the script `log()`s what was dropped.

**Phase 2 — Verify (adversarial, lens-diverse, not duplicated).** Per surviving unowned finding, verifiers get *distinct* lenses matched to how that finding could be wrong — not N copies of one question:
- *evidence-exists*: is the cited artifact actually at that line, saying that?
- *end-re-anchor*: the mechanism AC claims to serve a value another AC measures — did that value hold, or regress?
- *falsifiability*: can this criterion fail at all, or does it pass forever by construction?

One lens where the failure mode is single-dimensional; two or three where it genuinely isn't. Each verifier is prompted to **refute**, defaulting to refuted on uncertainty. A finding survives on lens coverage, not on vote count.

**Phase 3 — Synthesize.** The only genuine barrier in the script — it needs every confirmed finding at once. One agent produces cross-cutting themes ranked by member-hit-count, plus a per-member verdict table. Findings are carried as bare ordinals against system refs (slug, `AC-N`); I don't mint a finding-ID scheme in the prompts, because whatever I mint there becomes every downstream artifact's vocabulary.

**Then the gate is mine to present, not the script's to resolve.** The script returns data; I render the `Recommend` line and you decide. One carve-out: any confirmed finding whose remedy is a *new standing check* — a lint, a CI lane, a recurring validation step — I surface as an unmet clarification and do not dispatch. That's last-resort work needing your explicit yes, normally its own entity, and a sprint-wide review is precisely where a pile of them gets proposed at once.
