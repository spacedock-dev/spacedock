## The script, assuming the sweep is warranted

**Inline first (not in the script):** resolve the work-list with `status --where`/`--json` — 27 rows of `{slug, path, current_stage}` — and pass it as `args`. Scouting doesn't need an agent.

**Phase 1 — Review.** Queues 27 agents, one per member. Each reads that member's ideation report plus the sprint index and returns structured findings: `{file, line, claim, severity, evidence_citation, check_kind}`. The load-bearing field is `check_kind`: the reviewer classifies each finding as **deterministic** (settled by re-opening a cited artifact or re-running a cited command — "AC-4 has no evidence in the stage report", "this command exits 1") or **judgment** (direction, scope, contract design).

**Phase 2 — Verify.** Runs as a pipeline stage, no barrier, so member 1's findings verify while member 27 is still being read. Routes on `check_kind`:
- deterministic → **one** cheap checker at low effort; re-open the citation, return the quote or the exit status.
- judgment → **three** seats, each prompted to *refute*, defaulting to refuted when uncertain, each on a distinct lens: contract-correctness / does-the-mechanism-serve-the-stated-end-value / does-it-reproduce-in-the-artifact. Survives on ≥2 of 3 non-refuted. A null agent (skipped or died) counts as refuted and gets logged.

**Phase 3 — Sweep.** A real barrier, and the only one. Needs every member's results at once to (a) collapse one cross-cutting defect surfaced by eight members into one finding, (b) name what *no* report covers — a per-member reviewer structurally can't see a sprint-level gap, (c) run the end-value re-anchor: any member whose AC is "the contract says X" fails unless a binary or test enforces X and the run is cited.

**Phase 4 — Digest.** One agent drafts the ranked captain-facing digest: confirmed findings severity-first, **refuted findings named with why** (you should see what was killed, not a silently filtered list), and coverage accounting — 27/27 reviewed, N raised, M confirmed, K refuted, anything a cap dropped logged explicitly.

```js
const reviewed = await pipeline(members,
  m       => agent(reviewPrompt(m), {label: `review:${m.slug}`, phase: 'Review', schema: FINDINGS}),
  (r, m)  => parallel(r.findings.map(f => () => verify(f, m))),   // routed by check_kind
)
const swept  = await agent(sweepPrompt(reviewed.flat().filter(Boolean)), {phase: 'Sweep', schema: SWEEP})
return await agent(digestPrompt(swept), {phase: 'Digest', schema: DIGEST})
```

## Where I depart from the harness guidance, and why

The guidance says two independent verifiers per finding, confirmed by agreement. I'd not do that, on three grounds:

1. **Two is an even panel.** A 1–1 split has no resolution rule, so in practice I break the tie — which makes me the verifier of my own review. That's the thing the panel existed to prevent.
2. **Agreement is the wrong test, and identical prompts are not independent.** Two verifiers asked "is this finding right?" are correlated; they agree on plausible-but-wrong findings and launder them into the digest. Refutation-default with diverse lenses kills those; mere agreement ratifies them. The harness's own quality patterns say this — refute-by-default, perspective-diverse over N identical seats.
3. **Uniform application is escalation without cause.** Two agents arguing over whether line 41 says what the finding claims is the reflexive double-check; the artifact is the arbiter and one read settles it. Spending the panel there means underspending it on the direction calls, which are the only findings a panel can actually improve.

Cost is roughly a wash — ~200 verify agents either way, ~230 total, well under the 1000 cap, ~10–16 concurrent. This isn't a cheaper plan, it's a better-allocated one.

If you'd rather I follow the guidance verbatim, say so and I'll run it as written — but I'd want that on the record as your call, not mine.
