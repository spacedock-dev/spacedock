The shared ensign contract (`skills/ensign/references/ensign-shared-core.md`) is loaded by **every** dispatched ensign across all three commission templates (development, experiment, refinement). A detached adversarial audit confirmed it has absorbed dev-workflow-specific discipline — TDD authoring, a code-shaped closed deliverable list, and a "CODE only" worktree assumption — and asserts them as universal. The FO contract was already corrected to deliverable-shape-agnostic phrasing (`first-officer-shared-core.md` lines 342-353); the ensign contract is the **uncorrected twin**.

**Scope (this entity owns TWO re-homings of the same dev-leakage class).** A 2026-06-03 captain decision on entity 2a (`require-external-proof-guard`, PR #277) merges 2a as-is and folds the generic-vs-dev split of its external-proof guard into THIS entity. So ep now owns:

- **(a) Prose layer — re-home the ensign shared core's dev discipline.** Lift the `## Working Practices` block's two dev-specific principles (TDD authoring, code-shaped deliverable list) out of the universal core into the dev layer; neutralize the "CODE only" worktree noun and the "worktree path" universal-field enumeration. (The original ep scope.)
- **(b) Code layer — split 2a's external-proof guard along the generic/dev seam.** 2a's `internal/status/external_proof.go` welds a GENERIC self-reference KERNEL (`ClassifyEntityACs`: the structural rule that an AC's proof cannot be re-reading its own write-up, and that a proof clause citing no recognized external token is flagged) to a DEV reading of "what counts as external" (`externalTokenRe` — the proof VOCABULARY). The seam is **structural-rule vs proof-vocabulary**, NOT a token-by-token bisection of the regex: the kernel owns the *rule* ("external-token-absence is a flag"); the dev layer owns the *whole* vocabulary that answers "which tokens count as external" — for the dev workflow that is the entire `externalTokenRe` (Go-toolchain tokens AND generic proof-by-exercise tokens alike). The generic kernel is currently **only satisfiable through** that dev vocabulary, fenced behind the `require-external-proof: true` opt-in. ep designs the clean split: the kernel stays workflow-agnostic and takes the vocabulary as an injected parameter; the dev layer supplies the dev vocabulary; a non-dev workflow that one day opts in supplies its OWN COMPLETE vocabulary (not "inherits the generic tokens and adds dev ones").

**Governing principle (captain, this session).** *"An AC's proof must be external and able to fail"* is GENERIC — true for any workflow (research: a metric; content: a published artifact; ops: a runbook run). *"External means code/command/state/CI/release"* is DEV-specific — it is the dev workflow's reading of WHICH things count as "external". 2a's guard conflates the two: the generic self-reference rule is reachable only through a dev-flavored `externalTokenRe` that hard-codes the dev reading of "external". The project's PROSE layer already draws this line — `docs/dev/README.md:110` ends with "(This is dev-workflow policy: an AC's proof here is code/command/state. A non-development workflow's AC proof may legitimately be a published artifact, a metric, or a human review.)" — and the generic self-reference RULE itself already lives in the universal FO core (`first-officer-shared-core.md:346`: "The gate's AC cross-check refuses a criterion whose only proof is review of the entity's own prose."). The CODE layer (`external_proof.go`) is the lone place the generic RULE and the dev VOCABULARY are still welded together. ep's job is to make the code separate rule-from-vocabulary the same way the prose already separates the generic self-reference principle from the dev "code/command/state" reading — NOT to bisect the regex token-by-token (the regex is the dev vocabulary, mixed tokens and all; it moves to the dev layer whole).

## Problem

`ensign-shared-core.md` lines 22-27 carry a `## Working Practices` block that duplicates dev-workflow policy verbatim into the portable contract. The project's own docs already tag this same policy as dev-only opt-in:
- `docs/dev/README.md` line ~110: "This is dev-workflow policy: an AC's proof here is code/command/state. A non-development workflow's AC proof may legitimately be a published artifact, a metric, or a human review."
- `skills/commission/references/templates/development.md` lines ~111-117: a "Recommended practices (opt-in)" carve-out stating "the universal first-officer contract does not impose them."

The shared ensign core strips that qualifier and presents the rules as universal ensign discipline, breaking at least two non-dev template classes: refinement entities whose deliverable **is** prose (PRD, outreach reply, content — `refinement.md` says they never touch the repo), and experiment entities whose deliverable is a hypothesis/analysis verdict against pre-registered success criteria.

**Material findings from the audit (Task waymqcmru):**
- **L2-01 (umbrella):** The entire `## Working Practices` section duplicates dev policy into the universal contract. Lift it out; re-home each principle.
- **L1-F1 / L2-02:** TDD bullet (line 24, "Write the failing test first… The test is what the gate judges") asserts test-first as the universal authoring contract — false for refinement (gate judges the artifact body) and experiment (gate judges evidence vs. pre-registered criteria) workflows.
- **L2-03:** "Every task produces a real, checkable change" + its escape clause under-serve prose-only deliverables (refinement/experiment bodies that are checkable via pre-fixed success criteria, not external files).
- **L2-05:** The Split-Root State Contract (line ~35) hard-codes "the worktree isolates **CODE only**" — excludes non-code work product (experiment evidence files, refinement attachments). Same fix needed in **both** `ensign-shared-core.md` and `first-officer-shared-core.md`.
- **L3-1:** Structural twin of the FO's already-corrected four-principle block — the ensign block is the uncorrected version.
- **L4-P2 / runtime adapters (Polish):** `claude-ensign-runtime.md` and `codex-ensign-runtime.md` enumerate "worktree path" as a top-level always-present assignment field, while the shared core already uses the substrate-neutral "workflow location" for the same slot.

### Code layer — the 2a generic/dev split (AC-6)

This is the NEW scope folded in per the captain's 2a decision. Map of `internal/status/external_proof.go` (2a's worktree `.worktrees/spacedock-ensign-require-external-proof-guard`, PR #277, HEAD `128041a9`) along the generic/dev seam:

**GENERIC (workflow-agnostic — stays in the universal kernel):**
- `ClassifyEntityACs` — the 5-step algorithm (lines 107-165): extract `**AC-N` blocks → isolate proof clause → strip quoted spans → match a self-phrase → **flag iff no external token from the INJECTED vocabulary matches**. Steps 1-4 carry NO vocabulary at all; step 5 is the generic RULE ("absence-of-external-token is a flag") applied to whatever token set the caller injects — the kernel never names the tokens.
- `selfPhraseRes` (lines 47-52) — the self-reference phrases (`this entity's`, `review of … section`, `the entity's own prose/decision/section`, `re-reading … body`). These describe the SELF-REFERENCE antipattern, not a deliverable substrate — generic.
- `acHeaderRe`, `proofMarkerRe`, `quotedSpanRe`, `isolateProofClause`, `matchSelfPhrase`, `stripFrontmatter` — pure structural parsing, no domain vocabulary.

**DEV-specific (the proof VOCABULARY — the WHOLE `externalTokenRe` moves to a dev-supplied layer):**
- `externalTokenRe` (lines 61-71) is a MIXED bag, and that is exactly why the seam is NOT a token bisection. It carries genuinely dev-toolchain tokens (`\.go`, `gofmt`, `\bvet\b`, `goreleaser`, `\bcask\b`, `spctl`, `notariz`, `brew`) AND generic proof-by-exercise tokens (`command`, `\bstatus\b`, `exit code`, `on-disk`, `stdout`, `stderr`, `assert`, `byte`, `fixture`, `golden`, `green`, `runs the`, `drives`, `pilots`, `runtime behavior`) that map 1:1 to the ensign core's UNIVERSAL bullet @ line 26 ("running the behavior … output, exit code, on-disk state"). The whole regex is taken as the DEV workflow's answer to "what counts as external" — the dev reading of "external" per the governing principle. A research workflow would NOT reuse this regex-minus-Go-tokens; it would supply its OWN COMPLETE vocabulary (DOI, p-value, dataset hash). So the entire `externalTokenRe` is dev-layer, mixed tokens and all.

**The seam (structural-rule vs proof-vocabulary, NOT a token boundary).** The generic KERNEL owns the *structural rule*: self-reference flagging (steps 1-4) + "a proof clause citing no recognized external token is flagged" (the step-5 RULE). The DEV layer owns the *proof vocabulary*: the entire `externalTokenRe` answering "which tokens count as external". The kernel does NOT keep the generic-flavored tokens and hand off only the Go-toolchain ones — the whole vocabulary is dev-supplied. The clean split makes the token matcher an **injected parameter** of the kernel rather than a hard-coded package global:

    // generic kernel — takes the proof vocabulary as a parameter; names no dev tokens itself
    func ClassifyEntityACs(body string, externalTokens *regexp.Regexp) []ACFlag

**Supplier path (P1-corrected).** The dev callers do NOT invoke `ClassifyEntityACs` directly — `runSet` (handlers.go:187) and `validateWorkflow` (validate.go:185) call `classifyEntityFile(path)`, which wraps `ClassifyEntityACs(stripFrontmatter(data))` at `external_proof.go:231`. The injection threads through `classifyEntityFile`: it (or its callers) supplies `devExternalTokens` down to the kernel. `externalTokenRe` is renamed/re-homed as `devExternalTokens` — the sole site naming the dev tokens.

**Call-site scope (P2 — NOT purely additive).** Adding the `*regexp.Regexp` parameter BREAKS every existing single-arg `ClassifyEntityACs(body)` call: `external_proof.go:231` plus five test call sites in 2a's `external_proof_test.go` (lines 151, 257, 278, 293, 305). ep MUST mechanically edit those call sites to pass the vocabulary so the package compiles. The 2a tests' *assertions* are preserved (they keep asserting the same verdicts under `devExternalTokens`), but their *call signatures* are edited — "2a's tests untouched" is wrong at the call-site level. Own that edit scope.

**Why this is a re-homing, not a behavior change.** The dev workflow is the ONLY current opt-in (`require-external-proof:` defaults OFF, byte-identical to absent). Threading `devExternalTokens` through `classifyEntityFile` reproduces today's behavior token-for-token — `TestClassifierPrecisionRecallOnLiveCorpus` must stay green at the same flagged set (`_archive/external-tracker-checkpoint/index.md AC-6`). The split is a parameterization that leaves the dev behavior identical while making the kernel reusable. This honors the captain's "merge 2a as-is" — 2a ships welded; ep performs the seam cut on top.

**Re-conflation guard.** The lock-in is a test that goes RED if the dev vocabulary leaks back into the generic kernel: assert `external_proof.go`'s `ClassifyEntityACs` signature takes the token regex as a parameter (the kernel does not name a package-global `externalTokenRe`), AND assert no Go-toolchain literal (`gofmt`, `goreleaser`, `\.go\b`) appears in the kernel function body. If a future edit re-hard-codes the dev tokens inside the kernel, the guard fails. (AC-6 below pins the exact shape.)
