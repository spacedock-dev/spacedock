## Problem

The boot-resident core, the dispatch core, the gate flow, and the merge flow each interleave three layers of concern in one prose run: the L3 *intention* (what outcome the step reaches), the L2 *mechanics* (the exact git dance, the set→invoke→clear sequence, the dispatch-build invocation), and — where a verb has shipped — the L1 *automation* the FO calls. A capable model reads through all three and reconstructs the intention; a weak (Haiku) FO re-derives the mechanics inline every session and breaks them (the `w4` spike: `«state.commit»`'s `git -C` form paraphrased to `cd && git add` 2/3, `«dispatch»` dropped `subagent_type` from the emitted envelope 3/3). The sprint's binary-verb members push those mechanics into the binary, but there is no SUBSTRATE in the contract that lets a shipped verb *replace* its hand-followed recipe without a contract rewrite. Today every verb member would have to find-and-rewrite its own region of prose; nothing makes "this op is now a binary call" a one-line flip.

The prototype (`docs/dev/_proposals/state-repo-pointer-prototype.md`) names the cure: declare each op the flow invokes as a prose-function `«fn»(arg)` whose BODY either carries the hand-followed recipe (guillemets = L2, not yet code) or names the shipped verb it calls (backticks = L1, a binary). The flow reads as L3 intention; the L2/L1 mechanics live in the bodies; migrating a step is literally `«merge.guard»(slug)` → `` `spacedock merge guard <slug>` `` — the invocation never moves, only the body flips notation. This task is that substrate: re-express the five named cores as prose-function invocations so every sibling verb member's "the verb shipped" is a body guillemet→backtick flip, not a re-authoring.

Two facts from the live tree shape the scope:

- **Zero guillemets exist in the shipped contract today** (`grep -rc '«' skills/*/references/*.md` = 0 across all shipped contract files; `fo-tier-delegation`'s `«fo.tier»` lives only in its un-merged entity body, not in `skills/`). The notation is entirely prototype/proposal; this task is the FIRST landing of it into shipped scaffolding. There is no existing guillemet convention to preserve — only the prototype's grammar to adopt.
- **2y (`shared-merge-dispatch-contract`) is MERGED** and the host-neutral cores it produced now carry the sprint verbs the restructure backticks. `fo-dispatch-core.md` (`## Dispatch` / `## Reuse and Fresh Dispatch` / `## Dispatch Adapter` / `## Event Loop`) and `fo-merge-core.md` (`## Merge and Cleanup` / `### Ship-Local Ceremony` / `## Mod-Block Enforcement`) are the regions restructured; the work is against merged `main`, not a branch.

The deeper problem the ideation gate must settle is PROOF. This workflow's proof policy bans prose-grep over instruction files: "A string, substring, or regex match over an instruction file the model reads … never proves a behavioral claim. The matched text was written by the same implementer the check polices." A restructure whose only deliverable is contract prose is the textbook trap — "the contract now uses guillemets" is exactly the tautology the policy forbids. The completion checklist pre-empts this: the proof must be a contractlint backtick↔command-tree binding WITH A RED CONTROL, NEVER a prose-grep. The approach below is built around a check whose expected value comes from OUTSIDE the contract (the binary's actual command routing) plus a shipped-verb operability spot-check, so the AC cannot pass by spelling.

## Proposed approach

Re-express the five cores as prose-function invocations using the prototype's grammar verbatim: `«fn»(arg)` in the flow, a `## «fn»(arg): one-line intention` declaration block with `effect` / `done-when` / `block` bullets and a `→ shipped` (backtick) or `→ prose, becomes \`verb\`` migration-target line. Notation IS the migration status — guillemets = hand-followed L2; backticks = a shipped L1 verb. The flow that invokes a function never changes when its body flips.

### The non-grep proof mechanism (resolves checklist item 1)

The behavioral AC binds the contract's notation to an INDEPENDENT oracle that can diverge from it — the binary's actual command routing — with a RED control. The first ideation pass proposed binding against `newRootCommand(...).Commands()` recursively. **That oracle is wrong, and this re-ground corrects it** — exercised this session, not asserted:

- **Spike finding (the riskiest path, exercised).** A throwaway test inside `internal/cli` built `newRootCommand(...)` and walked `.Commands()`. Every top-level command (`state`, `merge`, `dispatch`, …) returns `children=0`. The subcommands (`state commit`, `merge guard`, `dispatch build`) are NOT cobra child commands — each parent sets `DisableFlagParsing: true` and routes its subcommand via a `switch args[0]` inside `RunE` (`cli.go:359,401`). So `.Commands()` recursion resolves ZERO multi-word verbs: it cannot see `merge guard` or `state commit` at all. The first pass's claim that "`dispatch` yields `build`/…; `state` yields `init`" via `.Commands()` is factually false.
- **The corrected oracle (exercised and proven to discriminate).** Invoke the verb's argv against the compiled root and inspect whether the routing REJECTED it. A shipped verb is accepted into its handler (which may then complain about a missing flag/arg); an un-shipped verb is rejected with a distinctive `"unknown …command"` stderr marker. A spike asserted this across all families — shipped (`merge guard`, `state commit|ready|sweep`, `dispatch build|show-stage-def`, `status`) never emit a marker; un-shipped (`merge teleport`, `state warp`, `dispatch next-action`, `gate assemble-verdict`, bare `gate`) always do — with zero false positives/negatives. The routing in `cli.go` is the oracle: a contract that backticks `spacedock dispatch next-action` before the verb ships FAILS (the binary rejects the argv), and a guillemet whose target verb now routes FAILS as "should-have-flipped." This is an independently-authored value (Go routing source) bound against the contract token, diverging under exactly the migration mistake we want to catch — NOT the banned heading-present/absent grep.
- **The rejection marker is NOT uniform — three forms at three sites (exercised, carry into implementation).** The check MUST recognize all three or a `gate`-family target mis-binds: (a) an absent TOP-LEVEL command rejects at the cobra root → `unknown command: {cmd}` (e.g. `gate assemble-verdict` → `unknown command: gate`); (b) an absent subcommand under a known parent rejects at that parent's `switch args[0]` default → `spacedock {cmd}: unknown subcommand (want: …)` (e.g. `merge teleport`, `state warp`); (c) `dispatch` emits its own form → `error: unknown dispatch subcommand: {sub}`. AC-1's resolver treats a verb as un-shipped if ANY of these three markers appears in stderr; matching only `"unknown subcommand"` would read a `gate`-family guillemet target as shipped (false-accept) and silently pass a should-have-flipped error.

Two halves of the AC:

1. **Verb-notation ↔ command-routing binding (an `internal/cli` structural check, NOT a prose-grep).** A new check extracts every backtick `` `spacedock …` `` verb token AND every `«fn»` guillemet declaration's `→` migration-target from the restructured cores, and binds each by INVOKING its argv against `newRootCommand(...)` and asserting the routing result against ALL THREE rejection markers above: a **backtick** verb MUST be accepted (none of the three markers in stderr); a **guillemet** target MUST be rejected (one of the three markers, at whichever site applies) — else it should have flipped. The check lives in `internal/cli` (not `internal/contractlint`) because `newRootCommand` / `run` are unexported — the check that drives the real routing must sit in the package that can call it. The contract-file walk reads the `skills/.../references/*.md` cores by relative path (same filesystem-oracle idiom as `boot_resident_closure_test.go`).
2. **The RED control (mirrors `boot_resident_closure_test.go`'s dangling-target guard).** A fixture plants (a) a backtick verb the binary does NOT route (`spacedock merge teleport`) and proves the check goes red, and (b) a guillemet whose `→` target IS routed (`spacedock merge guard`) and proves the should-have-flipped failure goes red. Non-vacuity is mutation-proven the way the cleanup member's controls are (stub the resolver to never reject → the planted-phantom control reds).

The verb-body flip is the gradable migration event: before a verb ships the check requires its argv REJECTED; after, ACCEPTED. AC-4 makes that flip the demonstration (flip one shipped body's notation, re-run the check, observe it re-binds; revert). The full multi-core operability proof (a Haiku FO driving the restructured contract end-to-end) is the sprint's terminal `haiku-drive-validation`; this member ships the substrate and is graded by the structural check (1) + RED control (2) plus the single-core operability spot-check (AC-3).
